# S20 — the drawing draft gets its own module

Research behind the split that took `DrawTool` and `DrawDraft` out of `crates/ui/src/contour_edit.rs`.
It stays after the commit because one file still covered two operations, and the boundary between
them is what the next drawing tool or grip rule reads; the outcome is in `plan/BACKLOG.md`.

## What was measured

- `crates/ui/src/contour_edit.rs` was 1111 production lines at `22e0e71`: contour editing
  (`ContourTarget`, `ContourEntry`, `ContourDraft`, `ContourEdit`) in 1–421 and drawing (`DrawTool`,
  `DrawDraft`, `DrawDraftError`, `DrawnPath`, `point_in_range`, `closing_segment`) in 423–1110. The
  test module below it was 1028 lines; 27 of its 43 tests built a `DrawDraft`.
- After the move: `contour_edit.rs` 430 production and 444 test lines; `draw.rs` 723 production
  lines; `draw_tests.rs` 588 test lines; `lib.rs` 52 lines. No ceiling of `plan/refactor.md` §3 is
  crossed: the largest module is 723 production lines, the largest `impl` under 400.
- The suite is unchanged (T1): 288 tests pass, the same assertions, with only the module path, the
  test file and two `use` lines changed.
- `git diff -M` reads as a move: `contour_edit.rs` loses the drawing block and `draw.rs` gains it
  unchanged; no body, signature or doc comment was rewritten.

## Decisions

- `DrawDraftError`, `DrawnPath`, `point_in_range` and the free `closing_segment` travelled with the
  draft: every one of them exists only for `DrawDraft`, and no contour code names them. Leaving them
  behind would have kept the drawing error type in the contour module.
- The 27 drawing tests moved to `crates/ui/src/draw_tests.rs`, declared from `draw.rs` as
  `#[cfg(test)] #[path = "draw_tests.rs"] mod tests;` (T2). The block was 584 lines, above T2's ~300,
  so it takes the sibling-file form rather than a module inside `draw.rs`. The assertions are
  untouched; only the indentation and the `use` lines changed.
- The contour tests stay in `contour_edit.rs`: 444 lines with the four fixtures they share, near
  T2's threshold and not worth a second file in a move.
- Both headers are contracts (H1–H6). `draw.rs` owns the tool grammar, the closing rule and the
  refusals (ADR 0048, 0076, 0077) and the one commit (ADR 0052); `contour_edit.rs` owns the working
  copy, its two corner modes (ADR 0075) and the ring and chain rules (ADR 0040, 0073). Each says
  `//! Changes when:` once, and neither repeats the other's reason.
- `lib.rs` re-exports `DrawDraft`, `DrawDraftError`, `DrawTool` and `DrawnPath` from `draw`, so the
  shell's single `use furnicraft_ui::{DrawDraft, DrawTool, …}` line needs no edit. Inside the crate
  the four callers import `crate::draw::…` directly; `DEFAULT_POLYGON_SIDES` was crate-private
  before and stays so, which is why it is not in the re-export list.
- `plan/map.md`'s *Drawing draft* row now points at `draw.rs`; the *Contour edit* row did not move.

## Ruled out

- Leaving the drawing tests in `contour_edit.rs` behind `use crate::draw::*`: a new draw tool would
  still reopen the contour module, which is the crossing the split removes (B2).
- Putting the tests inside `draw.rs`: 588 test lines beside 723 production lines is the file T2
  exists to avoid, and the entry asks for one move, not a second layout decision.
- Moving `DrawDraft::commit` into `editor/drawing.rs`: that module owns the work plane and the
  outcome, but the params and the "the path command created no node" sentence are the draft's own,
  and splitting them would put one command's dispatch in two modules (C7).
- Re-exporting the moved items only through `crate::draw` and editing the shell anyway: the shell is
  outside this task's `files:` hint, and the re-export costs one line (B8).
