# S19 — the editor splits by mode

Research behind the move that took `Editor` out of `crates/ui/src/lib.rs` and split it by the mode
that owns each method. It stays after the commit because "which mode owns this state" is the
question every later UI task asks; the outcome is in `plan/BACKLOG.md`.

## What was measured

- `crates/ui/src/lib.rs` was 1085 production lines at `e056268` (S18): one `impl Editor` of 966
  lines, 74 methods (60 of them `pub`), 17 fields, plus the crate header, 26 `mod` lines and 30
  `use` lines. The test module was 1377 lines below it, not counted in production.
- After the move: `lib.rs` 50 production lines; `editor/mod.rs` 47; `selection.rs` 111,
  `mesh.rs` 121, `contour.rs` 191, `drawing.rs` 149, `creation.rs` 214, `ribbon.rs` 172,
  `cards.rs` 172. The largest module is 214 lines, a third of B4's 600-line target.
- Public items per module are 3–16, under B6's 25. The largest `impl` block is 191 lines, under
  B4's 400-line target.
- The 288 UI tests are unchanged: the same assertions, only the import lines of the test module
  changed (T1).

## Decisions

- The test module moved from `lib.rs` to `editor/tests.rs` with `#[cfg(test)] mod tests;`. It was
  not optional here: three tests read the private `selection` field
  (`editor.selection.replace_all(...)`), and a field is visible only inside the module that defines
  the type and its descendants. Rewriting those tests to go through the public API would have
  changed what they assert, which T1 forbids. The file is the sibling-module form T2 describes,
  and no commit here changes logic, so the test move rides with the code move.
- The ribbon got its own module instead of joining `creation.rs`. The entry's shape named six
  modules and left `show_ribbon`, `apply_ribbon_actions`, the ribbon fields and the extrusion
  without a home; B3 rules out leaving them in `mod.rs`, and `cards.rs` would then hold two
  unrelated "changes when" reasons (B2). `ribbon.rs` also owns `extrude_path` and
  `set_extrude_height`, because the extrusion is one of its buttons and the height field is its
  state.
- Six helpers widened from private to `pub(super)`: `retain_open` (called by `cards`), `create_panel`,
  `create_assembly`, `arm_primitive`, `create_camera`, `create_light` (called by `ribbon`), and
  `apply_ribbon_actions`, `extrude_path`, `run_action` (called by the test module). `pub(super)`
  inside `editor/<mode>.rs` means "visible in the editor", so the crate's published surface is the
  same as before; no signature, body or doc comment changed (B8).
- `PendingPrimitive` moved to `creation.rs` as `pub(super)`, beside the two methods that build and
  consume it; `mod.rs` keeps the field and imports the type.
- The `Editor` type doc now says it is the composition root of the modes and that each method
  touches one mode's state, which is the B5 exception it claims.

## Ruled out

- One `impl Editor` per module behind `impl Editor` blocks in one file: it would have kept all 1085
  lines in one file, which is the finding, not the fix.
- Moving the pointer-mode state into the mode modules (a `MeshMode` type holding `Option<MeshEdit>`):
  four modes change each other's state on entry (`start_drawing_with` clears mesh, contour and the
  armed primitive), so the fields have to sit where both modes can see them. Splitting the fields
  would move the coupling into setters without removing it, and it is a behaviour shape change, not
  a move.
- Making the cards own their editor state (`PanelCard` holding the contour target): the inspector
  reads the same selection, mode and error that the tree writes, so the editor stays the one owner.
- Re-exporting `PendingPrimitive`, `ContourDraft` or the new modules from `lib.rs`: nothing outside
  the crate names them, and the crate surface is what the shell uses.
- Adding a characterisation test for the new headers (T4): the entry is a pure move, and every
  header describes methods that already have tests.
- Skipping the `pub(super)` widening by making the modes call each other through `mod.rs`
  wrappers: it would add nine one-line methods whose only job is to route, which L7 calls out.
