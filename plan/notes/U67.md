# U67 — Tool variants and the F1 list

Tool variants and the F1 list

## Variant tables (approved map)

| tool | variants (first is the default pin) | shortcut |
|---|---|---|
| circle | centre+radius, two points (diameter), three points, tangent to two lines | C |
| arc | two points, from centre, three points | A |
| rectangle | from corner, from centre | R |
| polygon | N sides (field 3–128), by edge | N |
| line | two points, by angle | L |
| polyline | continuous chain (no list until a second method exists) | P |
| offset | by distance, through a point | O |
| fillet | radius, two lines | F |
| chamfer | distance, two lines | H |
| dimension-radius | radius, diameter | — |

A tool with one variant has no caret and no list. Line and polyline are separate tools on the
ribbon (owner decision), not variants of each other.

## Anatomy (from the accepted mock)

- width 298; header row 34 with the icon, the tool name and the shortcut on the right;
- section captions 9.5 uppercase dim («Построение», «Дополнительно», «Касательные»);
- row 30: icon 17 in the tool family hue, label 11.5, shortcut 10.5 right, pin 12 at the far right;
- the active/pinned row carries the accent as a 2 px left bar and a control fill;
- no footer; the owner removed the Enter/Esc/pin sentence;
- the first row is focused when the list opens; the arrow keys move, Enter runs;
- the list flips to right-aligned when it would cross the window's right edge; it never leaves
  the window rect vertically either (flip up above the ribbon if needed at a tiny height).

## Behaviour

- A click on a tool with variants opens the list; it does not run anything.
- A click on a tool with one variant runs it immediately.
- The shortcut of a tool runs the pinned variant without opening the list.
- The pinned variant is a *global* setting (`appearance` or `ribbon` section; choose `ribbon`),
  default the first; pinning from the list writes it on the next settings save.
- Esc, an outside click and a tab change close the list; switching layout or opening a modal also
  closes it. The open tool is session view state and resets on restart.
- Picking a variant dispatches the same `ToolAction` the old ribbon cell dispatched, with the
  variant's parameter; the engine sees no new command id when the variant only changes input.

## Tests

- open/close via click, Esc, outside click, tab change;
- keyboard navigation and Enter;
- pinned variant drives a plain click and the shortcut;
- unknown pinned id falls back and does not crash;
- no document revision on open/close;
- the anchored rect stays inside the window at all four edges;
- a tool with one variant draws no caret;
- the list's rows come from the spec (no duplicate row).

## Ruled out

- The F3 shelf: pushes the scene and reads as a second ribbon.
- Repeat-last-variant on click: the owner wants the list every time.
- Remembering the last used variant: it would make the ribbon unpredictable.
- A per-project pin: the owner chose a global setting.
