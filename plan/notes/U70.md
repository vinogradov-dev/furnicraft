# U70 — Icons are coloured by semantic role

Icons are coloured by semantic role

## Role table

| family | dark ink | light ink | used by |
|---|---|---|---|
| draw | #58C8DC | #1C7C92 | create/modify sketch geometry (U69) |
| modify | #A98BF0 | #6B4BB0 | transform and edit commands |
| model | #6E9EF7 | #2E5CB8 | solids, bodies, booleans |
| scene | #55C7A4 | #237A5E | panels, hardware, cameras, lights |
| view | #B8C2CE | #5A6674 | navigation, projection, display |
| danger | #E06A6A | #B33A3A | destructive commands only |

The accent (#E0A24A / #A6620F) is UI chrome and must never be a role ink: an active tool is a
background and a border, not a recoloured glyph.

## Pipeline

- A master may use at most three inks from this table, at the existing tonal levels
  (`fill-opacity` 0.12–0.18 passive, 0.45–0.60 result); one ink may be the result colour.
- `IconFamily` lives on the icon (not on the theme directory): `contour/arc` is draw,
  `actions/delete` is danger, `view/frame-all` is view.
- `RoleRamp` maps each role hex to the theme's ink before the texture is uploaded, so one master
  serves dark and light; the mapping is a six-entry table per theme.
- The mono path is the alpha silhouette multiplied by the theme icon colour; it is the automatic
  fallback below 20 px and the `Never` mode.
- The cache key is `(uri, px, theme, mode)`; a theme or mode change re-rasterises, a widget state
  change only remultiplies.
- Disabled = alpha multiply; hover/press = one lighten step of the mapped ink (8–12 %), not a
  second table.
- Contrast: each role ink against `panel` and `band` ≥ 3:1 in both themes; the draw ink is the
  weakest on P2 and is the one to check first.

## Why 20 px

At 16 px a two-tone fill reads as a muddy blob and the outline loses its weight (AUDIT.md §2);
at 20 px the three tones separate. The threshold is a pixel count, not a point size, so a 0.75 UI
scale falls back automatically.

## Tests

- every preset × theme renders the expected role colour in the pixels;
- the alpha silhouette is identical dark vs light;
- mono at 16 px equals the tint path;
- every hex in every SVG is in the table;
- no icon has more than three inks;
- each role clears 3:1 on both themes;
- a mode switch re-rasterises once per `(uri, px)`.

## Ruled out

- One asset set per theme or per palette: the palette changes neutrals, not icon meaning.
- CSS variables, masks, gradients or a colour token language inside the SVG: the rasteriser does
  not resolve them, and the guide forbids the elements.
- Using the UI accent as a role ink: active state would disappear among the icons.
- Four inks: three faces and one outline is the most that survives at 22 px.
