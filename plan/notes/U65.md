# U65 — Field anatomy, commit policy and the command bar

Field anatomy, commit policy and the command bar

## Field anatomy

- label left, value right; field 76 × 22, right-aligned, `tabular-nums`, 4 px radius;
- no unit inside the editable string; the unit lives in the section header («Размеры, мм»,
  «Положение, мм», «Поворот, °») or as a dim suffix outside the box;
- the label is the drag target (scrub) and carries the reset-to-zero on a double click if the
  existing scrub already does; keep that behaviour;
- the section header is a caption, not a control; the card scrolls and its nodes fold.

## Commit policy

| kind | when it commits | examples |
|---|---|---|
| Live | every frame of a drag | width, height, X/Y/Z, angles |
| Debounced 150 ms | 150 ms after the last keystroke, or Enter/blur | typed numbers, primitive size |
| OnEnter | Enter or blur only | a value that triggers an expensive boolean |

- While the debounce is pending the old value stays valid; the field shows the new text.
- Invalid input: keep the old value, red border and a one-line error; Enter does not commit.
- One edit session per value: the drag and the keystrokes between focus-in and focus-out (or a
  500 ms idle gap) collapse to one undo entry; a second edit is a second entry.
- Esc during a drag restores the value the field had at focus-in; Esc after a committed edit is a
  normal undo, not a second path.

## Expensive rebuilds

- The engine already rebuilds by revision and the mesh cache reuses untouched nodes; the UI bumps
  the revision once per committed value.
- A rebuild over ~250 ms reports «Перестроение…» in the status bar; the last good geometry stays
  visible, the UI does not block and Esc cancels the pending command.
- Do not add a modal spinner; a status line and a disabled command bar are enough (Blender/AutoCAD
  practice).

## Command bar

- For extrude and boolean (operations with a preview), one bar at the bottom centre of the
  viewport: command name, the number field, the unit outside, ✓ (Enter) and ✕ (Esc).
- The preview is a session preview, not a document revision, until ✓.
- Double clicking ✓ applies once (the state flips to idle after the first); ✕ restores the pre-
  command state and removes the preview.
- No per-field Apply button anywhere; if a card currently draws one, remove it and route the value
  through the policy.

## Inventory to touch

- `panel_card.rs`: size, thickness, material, edge banding, machining fields;
- `placement_card.rs`: X/Y/Z and the Euler angles;
- `pivot_card.rs`: pivot local fields;
- `container_card.rs`, `camera_card.rs`, `light_card.rs`, `properties_card.rs`: numeric fields;
- `scrub.rs`: the shared field widget and the policy hook;
- `settings.rs`: the numeric presets and the UI scale field (already scrubs; keep it).

## Tests

- invalid text keeps value and revision; the error is shown;
- debounce commits once and not per character;
- Enter and blur commit; Escape restores during a drag;
- one undo per edit session, two sessions = two entries;
- the unit string is not in the editable buffer;
- the command bar is idempotent on double ✓ and restores on ✕;
- a slow rebuild reports busy and does not freeze the frame.

## Ruled out

- Per-field Apply: one more click for every value.
- Committing on every keystroke: three rebuilds for «120».
- A blocking modal for a slow rebuild: the window must stay usable.
- Units inside the field: they get selected with the number.
## What the implementation measured

- The field is one drawn box: `ui.allocate_space` reserves 76 x 22, `ui.interact(rect, id,
  click_and_drag)` is the only widget under that id and the TextEdit reuses it. An
  `allocate_exact_size(.., Sense::hover)` under the same id made egui drop the focus a frame
  after the click: a hover-sense widget tells egui the id cannot take focus.
- The editable buffer never holds a unit: the number is drawn right-aligned in the theme's
  monospace face (its tabular figures) and the unit is a dim caption allocated after the box.
- A Tab moves focus at the start of the next frame, so the field can lose focus without seeing a
  frame that reports `lost_focus`. Text left pending in the buffer is committed by the next frame
  the field draws without focus; that path is what keeps a typed value from being dropped.
- egui ends a drag on Escape, so Escape arrives on the frame that also reports `drag_stopped`.
  The cancel is read before the release hands a number over, and the drag remembers that it was
  cancelled so the remaining frames do not move the number.

## Commit policy as built

| kind | when it commits | examples |
|---|---|---|
| Live | every frame of a drag; typed text after 150 ms, Enter or blur | size, X/Y/Z, angles, colour, camera projection |
| OnRelease | the release of a drag; typed text after 150 ms, Enter or blur | chamfer, radius, bow, cutout rectangle and depth |

- The note asked for a third kind, `Debounced`, beside `Live` and `OnEnter`. Typed text is
  debounced in every field — committing per keystroke was ruled out — so a `Debounced` kind would
  behave exactly like `Live`; `OnRelease` is the distinct behaviour it was meant to name, and
  `OnEnter` for typing is already the Enter and blur rule.
- No per-field Apply is left in the placement, pivot, nominal-size, camera and light cards.

## One undo entry per value

- `Session::edit_scope` mints a token; `dispatch_in` merges consecutive dispatches that carry it
  and pushes the snapshot only on the first, so a drag of forty frames is one entry.
- `Session::cancel_edit` restores the snapshot the edit started from, drops the entry and clears
  redo, so Escape during a drag leaves no history at all.
- A field stores its token in egui memory and hands it back in `FieldOutcome::scope`; the card
  dispatches with it and closes it on the release or the blur of the following frame.
