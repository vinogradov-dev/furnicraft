# U72 — the panels no longer narrow the scene rectangle

the panels no longer narrow the scene rectangle

## What was measured

- `Chrome::content` (`apps/furnicraft/src/side_panels.rs`) narrowed the scene rectangle by the left
  panel's right edge plus `INSET` and the right panel's left edge minus `INSET`. That one rectangle
  fed `Layout::regions`, `view_region` (and so the renderer's camera aspect), `view_cluster::show`,
  `paint_view_frames` and `show_command_bar`, so folding the tree changed the aspect and panned the
  image.
- The scene image was already painted over the whole central area
  (`ui.painter().with_clip_rect(area).image(self.texture_id, area, …)`), so the furniture under a
  translucent panel was already drawn; only the split views and the overlays were narrowed.
- `Chrome::covers` is the guard every press goes through: `pointer_on_chrome` gates `layout.press`
  (border drag and activation), picking, drafts, placement, the gizmos and camera navigation.
- `frame_all` rebuilds `home_camera` from the scene bounds and calls `Layout::frame` on the active
  leaf; the fit therefore targets whatever rectangle `regions` hands out.
- Live, at 55 % and with the same camera: three launches with both panels expanded, folded and hidden
  render the grid, the model and the shelf at identical pixels outside the panel rectangles, and the
  split of the model's edges does not move. The only difference was the *selected* Back panel's tint:
  the tree body auto-selects the first panel on its first show (`editor/cards.rs`, `initialized`),
  and a folded tree draws no body, so no selection and no highlight. That is pre-existing and
  independent of the rectangle.
- ADR 0080 carried two stale clauses: "the split views tile only the uncovered content" (now false)
  and a "fit distance scaled by the covered share, target panned half the covered height" mechanism
  that no code implements (`home_camera` divides the radius by half the vertical fov).

## Decisions

- `Chrome::content` returns the central area below `ribbon.bottom()` and reads no panel rectangle.
  One rectangle is used by the layout, the renderer regions, the image, the cluster, the command bar
  and the frame painting, so a panel state cannot reach any of them.
- The ribbon band still sets the top: folding the ribbon reflows the views and the aspect, because
  that is the strip's height and not a panel's.
- `uncovered(rect, ribbon)` stays in `viewport`: it returns the rect unchanged now, and keeps a view
  that ever reaches the band from hiding the orientation widget under it.
- The ADR's framing clause now describes the code: *Frame all* fits the leaf rectangle that starts
  below the strip.
- The orientation widget sits in a rectangle that no longer avoids the panels; U73 owns that
  clearance and is the next task, so U72 does not invent a second rectangle that the next commit
  would delete.

## Ruled out

- Keeping the panel exclusion for the widget only: U73 redesigns the widget placement (ribbon and
  both panels, plus a popover switch), so a partial rect here would be rewritten at once.
- A `Chrome::scene` alias beside `content`: an alias is a second name for one function; the doc
  comment now says what the rectangle is.
- Narrowing the cluster by the panels again: the cluster is chrome and the panels are drawn above the
  central panel, so it only matters in a window below about 760 pt, where both expanded panels leave
  too little scene to use anyway.
