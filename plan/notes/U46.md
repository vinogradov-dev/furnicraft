# U46 — the chrome themes get their drawings

## What was measured

- 38 of the 74 declared icons were zero bytes, but only 15 of them sat on a live surface: the ten
  `view` glyphs the floating cluster asks for (`orbit`, `pan`, `zoom`, `layout`, `sliders` and the
  five shading styles) and the five `actions` glyphs `visible`, `hidden`, `lock`, `unlock`,
  `collapse`. The other 23 were declared for menus and dialogs that do not exist yet.
- `plan/debt.md` forbids drawing `primitives/cone` alone: the *Model* tab would offer a tool
  `PrimitiveKind` cannot build. That note predates U46 and still holds, so the file stays empty.
- `view/front`, `view/top`, `view/right`, `view/axon` in the task text are the four standard views of
  the owner's reference quad layout. Our split layout opens Front, Top, Left and Axonometric, and the
  preset list offers all six `OpeningView::ALL`; a four-of-six set would have left two rows as text.
- `scene_tree`'s `a_row_at_rest_reveals_nothing_and_a_flagged_row_keeps_its_toggle` asserted the
  placeholder captions ("Show", "Unlock"). It was written against empty SVGs (U48 note) and had to
  follow the glyph.

## Decisions

- Every declared icon is drawn except `primitives/cone`: the 25 remaining `actions`, the ten `view`
  cluster glyphs, `bodies/revolve` and `bodies/sweep`. A complete theme is cheaper to keep than a
  per-surface subset, and the window theme already ships glyphs for a frame that is off by default.
- Six standard views (`axon`, `front`, `left`, `top`, `right`, `bottom`) were added rather than the
  four the entry names, so all six presets in the layout popover carry a glyph. Each is a screen plane
  with a bold arrow: six directions, one family, ~22–23 % coverage.
- `actions/command` is drawn and the palette header draws it: the palette is the surface the entry
  names, and a heading is the only place a command glyph belongs.
- The preset popover now draws `preset_row` (glyph, name, selected face) instead of text buttons.
  `view_cluster::preset_icon` is the one mapping from `OpeningView` to `Icon`, and
  `every_view_preset_has_its_own_drawn_glyph` keeps the six distinct and drawn.
- `every_chrome_icon_is_drawn` guards the three chrome themes; the tree test now counts painted
  rasters (`Shape::Mesh`) instead of caption text.

## Drawing notes

- Shading styles share one isometric cube and differ structurally, never by tone: `shaded` is a
  filled silhouette with no inner edges, `shaded-edges` fills it and draws the inner Y at 2.4,
  `wireframe` drops the fill, `xray` adds a wire core (diamond) and `translucent` a solid body dot.
- Service glyphs that a single stroke cannot bring to the 20 % floor got a second element: `remove`
  is a minus between two list rules, `expand`/`collapse` are double chevrons, `cancel` is a solid
  back arrow, `confirm` a long heavy check.
- `view/orbit` is a sphere with a tilted orbit ring and a moon; a flat ellipse plus a centre dot read
  as `actions/visible`'s eye.
- `view/revolve` is an axis, a passive profile and one swept arc with a head; `view/sweep` is a
  passive start profile and a result-tone end profile on one curved path.
- Footprint failures came from strokes, not from paths: a 2.2 stroke at `x = 3.6` leaves the grid at
  2.3. Every figure keeps a stroke half-width inside `3..21`; measured at 64 px through the same
  rasteriser the UI uses.

## Ruled out

- Drawing `primitives/cone` to empty the last placeholder (see the debt entry it would violate).
- Four preset glyphs only (see above); `left` and `bottom` cost two files and remove two text rows.
- A wedge-only direction mark for the presets: at 20/16 px the wedge shrank to a dot. The frame and
  the in-frame arrow survive down to 16 px.
- Reusing `actions/visible`/`hidden` for the orbit or any view glyph: a service eye and a navigation
  orbit are different families (`STYLE_GUIDE.md` §1.1).
- A `cargo xtask icons --sheet` subcommand (AUDIT §5 step 3): the contact sheets behind this task
  were throwaway renders in `/tmp`, and the repository's own test already measures footprint,
  coverage and legibility at 16 px.
