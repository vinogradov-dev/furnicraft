# S18 — the editor gives up the document rules it holds

Research behind the move that took three document rules out of `Editor` (F2). It stays after the
commit because "which rule belongs to which layer, and why" is what the next UI split inherits; the
outcome is in `plan/BACKLOG.md`.

## What was measured

- `crates/ui/src/lib.rs` was 1158 production lines and 1380 test lines at `1f361e1` (S17). It is
  1084 production lines now; the test module did not move, so the 74-line drop is the three helpers
  plus the default-size function and their comments.
- `crates/ui/src/target.rs` is 75 production lines, 0 test lines: `resolve_viewport_pick`,
  `creation_target`, `child_containing`.
- `crates/model/src/project/query.rs` went from 311p/63t to 327p/107t: the new query is 17
  production lines and the characterisation test is 44.
- `crates/engine/src/panel_cmds/panel.rs` went from 411p to 438p: two associated constants, the
  default-size function and its refusal helper.
- The suite is unchanged (T1): the same assertions pass, with three call sites renamed —
  `default_panel_size()` became `PanelCreate::default_nominal_size()` in `create_panel`, the palette
  builder and one test fixture.

## Decisions

- `Project::placement_in_parent` lives beside `world_placement`, its inverse operation. It returns
  `Result<Placement, ProjectError>`: `NodeNotFound` for a parent that is not in the tree and
  `PlacementCompose` for a frame that is not rigid. No new variant: the inverse of a stored placement
  cannot fail unless the stored frame is already broken, and the existing variant names the frame.
- `ProjectError` is a model type, so the UI maps it with `to_string()` at the same two call sites
  that already map command errors; nothing parses it.
- `PanelCreate::default_nominal_size` owns 600 × 400 as `DEFAULT_LENGTH_MM`/`DEFAULT_WIDTH_MM` on the
  command type (C7). A caller cannot override it and the ribbon and the palette cannot disagree.
  The failure path returns `CommandError::InvalidParams` for `panel.create`: the constants are the
  command's own, so a mismatch is a defect reported like any other rejected parameter rather than
  an `expect`.
- The pick and target rules stay in the UI layer, in their own module, as `pub(crate)`: ADR 0022
  puts the picking rule next to the open set and ADR 0056 puts the creation target in the editor.
  Neither is a project query, and moving them to `model` would need the open set in the document.
- The new model test checks a rotated parent twice: the parent is placed at (100, 0, 0) and turned
  +90° about Z, the world placement at (30, −10, 5) comes back as (−10, 70, 5) with its X axis on
  the parent's −Y, and composing the parent frame back reproduces the world placement. Exact
  equality is not used for the round trip: `compose` re-normalises the quaternion and introduces
  3e-14, so the test compares the translation and the rotation dot like `placement.rs` does.
- `plan/map.md` gained a row for the two rules and the ribbon row now points at `target.rs` for
  `creation_target`.

## Ruled out

- Making the conversion a method on `Placement` (for example `Placement::in_parent`): it needs the
  tree to find the parent's world frame, so it is a project query, not a placement operation.
- A new `ProjectError` variant such as `FrameCompose { id }`: C8 wants the error to name what the
  user can act on, and "container {id} has a placement that cannot be composed" already does.
- Moving `child_containing` into `model`: its only caller is the double-click rule, which already
  takes the open set; a tree walk alone is not a query any other layer asks for.
- Amending ADR 0022 or ADR 0056: both rules stayed in the UI layer, only their file changed, and the
  ADRs do not name the path.
- Adding a UI test for the module header's contract (T4): the picking and target rules already have
  tests through `Editor::select_viewport_hit`, `enter_viewport_level` and `creation_target`, so a
  second characterisation test would only copy them.
- Moving the test module beside the source (T2): optional and never mixed into a move commit.
