# U68 — The ribbon spec and the tab map

The ribbon spec and the tab map

## Map (id — group — tools, most used first)

- sketch — Создать: line, polyline, rectangle, circle, arc, polygon (variants in U67).
- sketch — Изменить: trim, extend, offset, fillet, chamfer, break.
- sketch — Опорные: construction-horizontal, construction-vertical, construction-parallel, construction-angle.
- sketch — Размеры: dimension-linear, dimension-angular, dimension-radius.
- sketch — Булевы: boolean-union, boolean-subtract, boolean-intersect.
- model — Примитивы: cube, cylinder, sphere, cone, pyramid (pyramid planned).
- model — Создать: extrude, revolve, loft, sweep (loft/sweep planned).
- model — Булевы: union, subtract, intersect.
- model — Грани: chamfer, fillet, shell, offset-face, delete-face (most planned).
- model — Тела: join, split, scale, mirror.
- furniture — Панели: panel, contour-panel; Обработка: drill, groove, edgeband, hinge-hole;
  Крепёж: confirmat, cam, dowel, minifix, shelf-pin; Фурнитура: hinge, runner, handle, foot;
  Проверка: collisions, parts-list, cut-list. Most planned; draw the tab only when a tool is live.
- scene — Объекты: camera, light, assembly, group; Виды: named-view, standard-view;
  Материалы: catalogue, assign.
- view — Проекция: projection, frame-all; Отображение: style, grid, contours, shadows, section;
  Раскладка: layout-1, layout-2, layout-4, maximize; Навигация: orbit, pan, zoom (gestures).

Ids are `tab.group.tool`; a group name is reused across tabs because the commands differ
(`sketch.boolean.union` vs `model.boolean.union`). A variant id is `tab.group.tool.variant`.

## Current code (measured before the change)

- `RibbonTab` is an enum with `ALL`, `columns()` (hardcoded 0/6/13/4/3), `label`, `id`, `groups`.
- `ToolGroup` is an enum with `ALL`, `label`, `theme`; `show_group_row` matches the group and calls
  `icons::ribbon_button` per tool.
- `ToolAction` carries the click; `RibbonContext` carries availability; `Toolbars` holds open/tab
  and the numeric texts; `height(open)` is 130 px today.
- The cell width is `RibbonMetrics::measure` over `columns()`; with a spec it becomes the maximum
  tool count of any group in any tab.

## Shape

- `spec.rs`: const tables + accessors (`tabs()`, `groups(tab)`, `tools(group)`), no allocation per
  frame.
- `ToolSpec.state: ToolState { Live, Planned }`; planned rows are skipped until the command lands.
- `enabled` stays a code function per tool (e.g. extrude needs a closed path), never a data field.
- The renderer draws tabs, groups, captions and cells from the spec; the group hue comes from
  `IconFamily`; the caption band is the dark strip.
- Height: 2 + 28 + 2 + 30 + 12 ≈ 74 → target 72 with the existing margins; collapsed = tab row 29.
- Keep the open state in settings (`ribbon.open`), default true, `#[serde(default)]`.
- Vocabulary is `furnicraft-text`: Эскиз, Модель, Мебель, Сцена, Вид; Создать, Изменить, Опорные,
  Размеры, Булевы; tool labels from the map.

## Tests

- every tab id, group id and tool id is unique;
- every `ToolAction` that exists appears exactly once;
- a planned tool is not drawn;
- a tab with no live tool is not drawn;
- the measured cell uses the widest group, not a constant;
- `height(true)` is 72 and `height(false)` is 29;
- the open state and the active tab round-trip through settings;
- the ribbon draws without a document (the context is a snapshot).

## Ruled out

- Keeping the three enums and adding arms: the map would still be code.
- One visible tool per group: `Создать` needs line and polyline side by side.
- A runtime JSON/TOML layout: not until level B (user panels).

## What the session measured and built (2026-11-12)

- The map is `crates/ui/src/toolbars/spec.rs`: `TabSpec` → `GroupSpec` → `CellSpec` → `ToolSpec` /
  `FieldSpec` → `VariantSpec`, every row a constant, every id namespaced by its parent. The sketched
  shape changed in three places, each for a measured reason:
  - `GroupSpec.cells` is an ordered list of `Tool` and `Field` instead of `tools`, because the sketch
    field sits *after* the polygon it configures and the order is part of the design; `columns()` sums
    the live cells, a field taking two.
  - `ToolSpec.icon` is `Option<Icon>` and `ToolSpec.run` is `Option<ToolKind>`; a planned row carries
    neither, which is what makes "planned" a datum rather than a special case, and the one code a row
    holds (`ToolKind`) is matched once in `ready()`, never in the drawing loop.
  - `shortcut` is the printed label (`"L"`, `"Shift+R"`), still derived from `shortcut(DrawTool)` so the
    key handler and the hint cannot drift.
- The four extra draw tools stay reachable: `ArcFromCenter`, `RectangleFromCenter`,
  `RectangleFromCenterDirected` and `CircleThreePoints` became variants of `arc`, `rectangle` and
  `circle`. A click runs the tool's own method (U67 pins the variant), and each variant keeps its
  shortcut, so nothing is lost while the list is missing.
- The «Черновик» group is kept at the end of *Sketch*: the approved map has no home for *Close* and
  *Cancel*, and `ToolAction::CloseDrawing`/`CancelDrawing` are live. They move to U65's command bar
  when it lands. `ToolAction::ClearCreationParent` was dead (the status bar has its own
  `StatusAction`) and is gone.
- *Panel* moved from the old *Scene* tab to *Furniture* (the map's `furniture.panels.panel`), so
  *Furniture* is drawn with one live cell. *Scene* keeps camera, light and assembly.
- Metrics adopted exactly (`RIBBON_TAB_HEIGHT` 28, `RIBBON_ROW_HEIGHT` 30, `RIBBON_CAPTION_HEIGHT` 12,
  `RIBBON_CELL_WIDTH` 34, `RIBBON_RULE` 1): folded is 28 + 1 = 29 and open is 28 + 1 + 30 + 12 + 1 = 72,
  so `RIBBON_FRAME_MARGIN`'s vertical margin is now 0 and the drawn strip equals the reserved band.
  `RibbonMetrics`, the 108–112 caption-cell band, the elision, the caption: `ribbon_button` and the
  horizontal scroll area are gone (ADR 0091, which supersedes the metrics of 0067).
- The two shades are derived, not stored: `theme::ribbon` is `mix(surface, panel, 40)` (lands on P1's
  `#1F242B` dark and exactly on `#F2F4F6` light) and `theme::band` is the chrome. A palette field `egui`
  cannot carry would need a second store for no visible gain.
- The ribbon cell is `icons::ribbon_cell`: the glyph at 22 pt, the face from `ribbon_face`, the hint on
  hover and as the accessible name, and the first word of the hint when the asset is a placeholder.
- A group widens to its caption when the caption is wider than its cells (the one-tool *Panels* group
  would otherwise clip «ПАНЕЛИ»), so the drawn row is not always `columns × 34`. The widest row of the
  map is ten cells (≈400 pt), well inside the 640 pt minimum window, which is why the body no longer
  scrolls sideways.
- The fold persists as `Settings::ribbon` (`#[serde(default)]`, open by default). `Document::new`
  applies it, `main.rs::sync_ribbon_fold` writes it on the one frame it changes and hands it to every
  open tab, since the ribbon is window chrome and not one tab's property.
- Checked by eye: the sketch tab open, the model tab open (disabled extrude, both fields) and the
  folded ribbon with `ribbon.open: false` in the settings file; three window captures. The tab row, the
  tool row, the caption bands, the group dividers and the 29/72 band all read as measured.

### U75 amendment (2026-11-12)

- The owner read the caption band as a hole: `theme::band` is the chrome, the darkest surface of the
  window, and the 12 pt band left the 9.5 pt capitals touching the tool row above and the rule below.
  `RIBBON_CAPTION_HEIGHT` is 16 now, so the cap ink keeps about 4.5 pt of air on each side, and the
  band is `theme::caption_band` = `mix(control, band, 30)` — one step off the button tone toward the
  chrome, never the chrome itself. On the light variants the chrome is the *lighter* of the two, so
  the same mix puts the band just under a control instead of just over the chrome; either way it is
  between the two and no longer the darkest surface.
- The name is placed by its *cap block* — the top of the tallest glyph to the baseline — not by its
  line box, which carries the descent, and not by its whole ink, where a `Д` leg or a `Ц` tail would
  lift the word off the line its neighbours share. Every caption of the strip now sits on one
  baseline, 4.7 pt from each edge of the 16 pt band; the legs of `СОЗДАТЬ` hang 2.7 pt above the
  rule, as a descender does.
- `height(true)` is 76 (28 + 1 + 30 + 16 + 1); the folded 29 is unchanged, so the shell, the side
  panels and the framing still reserve exactly what the strip draws and only the goldens moved.
- Measured on the live window (a fullscreen 2560 x 1600 capture at 1.5 scale; the dark run in Russian
  and the light one in English): the dark band is `#23292f` between the `#1d2128` ribbon surface and a
  `#2a3037` control, so it reads as a quiet strip instead of the `#14171b` hole; on paper the band is
  `#e5e8eb` under the `#f0f1f4` surface. The tab row, the tool row and the status bar read as before.

### Ruled out

- A palette `ribbon`/`band` token: `Palette` maps onto `egui::Visuals`, which has no slot for a second
  surface shade; the derivation is within a few units of the approved table.
- Keeping the caption under every glyph: the approved metric is a 34 x 30 cell, and the name comes from
  the hint until U67's list.
- A planned tool drawn disabled: the map would become a wall of grey and a tab would be drawn for tools
  nobody can use.
