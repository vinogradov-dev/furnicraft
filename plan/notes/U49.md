# U49 — one typed message table behind a language switch

## What was measured

- Before: about 730 user-facing literals in `crates/ui` (≈530) and `apps/furnicraft` (≈200), 51
  `CommandSpec` labels across `crates/engine/src`, and no language anywhere in the build.
- The four places that had to change shape rather than just move a string: `CommandSpec::label`
  (engine), `OpeningView::label` / `shading_label` / `shading_caption` (display), `DrawTool::label`
  (draw) and `DrawTool::strip_label` (toolbars) — each returned `&'static str` to a caller that had
  no language.
- `Settings` is versioned JSON with `#[serde(default)]`, so a new `appearance.language` field opens
  an older workspace file in English without a version bump.

## Decisions

- `crates/text` is L0 with no dependencies. `Lang::COUNT = Lang::ALL.len()`, and every row is
  `[&'static str; Lang::COUNT]`, so a third language is a compile error in every row, not a fallback.
- The `messages!` macro generates the enum, `Message::ALL` and `Message::table` from one list, so a
  row cannot exist in one and not the other. Rows are grouped by the surface that draws them.
- A sentence with a value carries `{}` and `Message::with`; a counted sentence is a `Counted` from
  `Message::counted(n, one, few, many)` that picks Russian's one/few/many itself.
- The shell publishes `Settings::appearance.language` on the egui context once per frame
  (`furnicraft_ui::set_language`). Threading a `Lang` through every card would have touched ~40
  signatures for one caption each; the context is already the place the UI keeps view state.
- Pure functions that return words take `Lang` explicitly (`OpeningView::label`, `shading_label`,
  `DrawTool::label`, `diagnostic_message`, `readout`), because they are testable without a context.
- `Message` implements `Display` as its English sentence: `thiserror` messages stay one language for
  logs and tests. A refusal that reaches the screen is mapped at the UI boundary
  (`length_error`, `degrees_error`), never printed raw.
- A generated name (`{} drawing`, a palette-created panel/assembly/camera/light/group) is written in
  the language that created it and never re-derived, so a switch renames nothing.
- The ribbon cell floor moved 104 → 108 pt: the longest Russian caption after translation measures
  98 pt at the 10.5 pt caption size, and the padding brings the floor to 106 (ADR 0067 amended).

## Ruled out

- A `gettext`-style catalogue keyed by the English sentence: the key would be the sentence, so two
  identical English sentences would share one translation and a missing one would fall back.
- A global `static AtomicU8` language: it would make parallel tests share state and give `crates/text`
  a hidden channel. The egui context is the same channel the UI already uses for view state.
- A `Lang` parameter on every drawing function: ~40 signatures for one caption each, and the cards
  already take `ui`, which carries the context.
- Translating `thiserror` messages: `model`, `units` and `project` stay English for logs and tests;
  the UI maps the two error kinds a field can show. Engine and drag errors still surface as their
  English detail, which is a known gap (`plan/debt.md`).
