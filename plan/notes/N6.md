# N6 — the empty-space tool, measured by the model and painted by the shell

## What was measured

- The furniture surfaces the move rule measures (`crates/model/src/project/move_query.rs`) were a
  private `SurfaceBox { id, min, max, shell }`; the probe needed the same boxes plus the kind that
  owns each face. They moved to `project/surface.rs`, shared by both queries, so the mover and the
  niche cannot disagree about where a surface is (the N5 note asked for exactly this).
- The session preview overlay (`crates/engine/src/preview.rs`) is a `BTreeMap<Id, Geometry>`, and the
  frame builder visits the document's nodes. A part that does not exist yet has no id, so the ghost
  could not be an overlay entry without inventing a key the evaluator does not know. ADR 0104 records
  that a missing node's ghost is shell paint; the overlay keeps its job for existing nodes.
- The registry already carried `Fill::HeightAndDepth` on `30.10.00 vertical-panel` and
  `Fill::WidthAndDepth` on `30.11.00 horizontal-panel`; no class row changed. The tool binds to those
  two rows through `ClassCode::VERTICAL_PANEL` / `HORIZONTAL_PANEL`, and a class test proves each
  constant still names the row that carries the trait.
- `panel.create` took no class, so a fill that assigned one would have been a second command and a
  second undo entry. `PanelCreate::class: Option<ClassCode>` is written by the same command, and the
  engine test `a_classed_panel_lands_in_one_undo_step` proves one undo removes the whole part.
- The `files:` hint named `crates/model/src/project/query.rs` and `apps/furnicraft/src/gizmo.rs`; the
  query and the tool are new modules (`niche.rs`, `surface.rs`, `fill_gizmo.rs`, `editor/fill.rs`),
  and the hint was corrected with `cargo xtask task set N6 --field files --files …`.

## Decisions

- `Project::probe(point, direction)` walks every product shell, panel and object once and answers the
  first surface the ray meets, with `SurfaceKind::{Envelope, Panel, Body, Shell}`. The innermost
  envelope containing the point is reported as an **envelope** face, not as one more shell, so a
  piece standing inside another is still a shell hit when the ray reaches it (ADR 0102).
- `Project::niche(point)` casts six rays along the product's own axes and answers `Niche { product,
  local_min, size, min, shape }`: the box in the product frame (the frame a panel is placed in) plus
  the anchored corner in world millimetres. It is derived on every call and stored nowhere.
- A product turned off the world axes has no world-box answer, so `niche` refuses it (`None`); the
  probe still answers. N7 answers the shaped case.
- The tool fills for the **open** product only; `niche.product != active_product` is a refusal. The
  ribbon disables both cells with the sentence that says why (`FillNeedsProduct`,
  `FillNeedsMaterial`, `FillNeedsFillTrait`), and `Editor::arm_fill` refuses for the same reasons.
- The free axis follows the pointer in whole millimetres: a shelf's height, a post's place along the
  width. The measured sides keep the niche's micrometre precision, so a part is flush with the walls
  it was cut to; only the pointer's coordinate is rounded. The free position is clamped so the whole
  thickness stays inside the void, and a void thinner than the material is refused.
- A post is the vertical-panel row with local X down the height and local Z along the niche's free
  axis (`DQuat::from_rotation_y(π/2)`); a shelf is the horizontal-panel row lying on its plane, so the
  niche's width and depth are the panel's length and width.
- The arm lives in the editor (`FillArm { class, fill }`) because it is the button's activity; the
  measurement and the ghost live in the shell (`fill_gizmo`), because they need the camera. A click
  calls `Editor::create_panel_sized` with the ghost's exact `nominal_size` and `placement`, so the
  created part and the picture are the same numbers.

## Ruled out

- Extending the preview overlay with a non-node key: it is a second preview mechanism, and the domain
  already describes the niche as a wireframe with callouts (`docs/domain/products.md` §4).
- A class picker popup on the ribbon for the fill: the two canonical fill rows are the tool, and the
  guard still refuses any other class at the arm; a picker can come when a tool needs several fills.
- Rounding the measured sides to whole millimetres: a panel would stop being flush with a wall that
  sits on a fractional millimetre, and the document stores micrometres anyway.
- A new `panel.fill` command: the ghost is a parametric rule in the shell, and `panel.create` already
  writes exactly what the tool measured; a second command would duplicate its validation.

## Verification

Unit tests over the model (envelope, panel, object body, another shell, a part shrinking a niche on
the measured axis, a shelf splitting the piece into two niches, a world corner and a shape, a turned
piece refused, hostile input), over the tool (shelf and post ghost sizes and placements, clamping,
a too-thin void, the envelope entry), over the ribbon and the editor (the disabled cell, the arm, the
refusals, the toggle, the sized classed panel), and two shell tests: a headless frame that clicks the
ghost and proves the created panel equals it and one undo removes it, plus an offscreen shape check of
the wireframe and the three sizes. `target/ui-shots/fill-ghost.png` is the offscreen picture of the
real frame with the ghost, and it reads: the accent wireframe inside the dashed envelope with its
size callouts. The 1 mm feel was not driven in a live window in this session; the rounding and the
clamp are covered by the tool tests.
