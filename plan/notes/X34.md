# X34 — The audit found two concepts already split in the data but not in the vocabulary

The audit found two concepts already split in the data but not in the vocabulary. `Placement::translation` is the origin (implicit, no second field); `PivotLocal` is the exact offset. The creation layer called the origin a pivot, and a panel's zero pivot was shown as the base corner. A `rebase_origin` on an authored pivot had to preserve `pivot_world`, otherwise a rotation handle would move silently. The owner chose variant A for panels, legacy container centres stay legacy offsets, and the origin stays implicit.

Operations now: `rebase_origin` rewrites vertices and translation, keeps every world vertex and `pivot_world` (`pivot_local_new = pivot_local_old - anchor`; in world terms `R_world^-1 * (pivot_world - origin_world)`); `set_pivot`/`center_pivot` change only the offset; `placement.world_zero` changes only the translation. A panel's offset is always zero and `set_pivot`/`center_pivot` refuse it. Schema 20 stores `pivot_local`, reads a schema-19 `pivot` through a serde alias, and the new `scene-v20.fcs` golden joins the compatibility set.

Test note: the first version of the rotated-parent test used the node's local rotation in the owner's formula and failed; the composed world rotation is the correct one. That is exactly the formula ADR 0088 records.
