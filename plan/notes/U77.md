# U77 — the shell's one frame is callable without a window

## What was measured

- `apps/furnicraft/src/main.rs` at `81f9e6b`: `impl eframe::App::ui` held the whole 200-line frame
  body, so nothing but the window could drive the interface.
- The GPU was touched in exactly five places in `document.rs`: register and first upload in `new`,
  upload in `upload_scene`, resize in `viewport`, `render_views` plus `Painter::image` in `viewport`,
  and `free_texture` in the shell's `forget`. Everything else — evaluation, the layout, picking, the
  gizmos, the overlays — is CPU work that already ran in tests.
- `tabs.rs` needed no change: `Tabs::new(document)` and `Tabs::len` already build and count tabs
  without a window, so the hint was wider than the seam.

## Decisions

- One `Option<Target>` on `Document` (render state, renderer, texture) instead of three separate
  options: a tab either has a target or it does not, and the type says so.
- A headless viewport fills its rectangle with `visuals().extreme_bg_color` where the scene image
  would be, so the scene rectangle, the layer order and the overlays are the real ones and only the
  pixels differ.
- `FurniCraftApp::build(ctx, render_state, store, loaded, session)` is the single place the window
  and a test part; `new` (GPU, real workspace) and a `cfg(test)` `headless` are its two callers.
- The scratch path comes from `furnicraft_testkit::scratch_dir`, and `SettingsStore::at` stays
  `cfg(test)`, so a headless run cannot reach the workspace file in the OS config directory.
- The frame helper clears `FullOutput::textures_delta`: epaint asserts on drop that a delta was
  applied, and a test has no renderer to apply it to.

## Ruled out

- Faking an `egui_wgpu::RenderState` for the tests: it owns a device, a queue and a renderer, so a
  fake needs a headless adapter or `unsafe` — heavier than one `Option` and a lie about which code
  ran.
- A paint callback: the shell draws its target through `register_native_texture` and `Painter::image`
  and never uses a callback, so the optional target skips both and the wording of the entry was the
  plan's, not the code's.
- Splitting `Document::viewport` so that the GPU part becomes its own function: the wrapped block is
  the two device touches plus the image, and a function around it would thread a dozen locals for
  nothing.
- Giving `Document::new` a device-free sibling: the only difference is `render_state`, so a sibling
  would duplicate the evaluation, the layout and the fit.
