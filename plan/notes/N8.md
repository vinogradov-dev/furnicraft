# N8 — What was measured

## What was measured

- The model already answers everything the fields need: `Project::niche` returns the void's box in
  the product frame, and `FillGhost` draws the panel's two thickness faces (`world` and `top`). The
  free axis of a fill is the panel's own Z for both rows — product Z for a shelf, product X for a
  post — so `fill_gizmo::free_axis` is the only new fact and the field numbers come from the niche,
  never from a second probe.
- `FillGizmo::plan` could only follow the pointer; `plan_at` now takes the free coordinate and the
  `hover` cache key includes it, so a typed number pins the ghost against the moving pointer.
- `Scrub` (`crates/ui/src/scrub.rs`, ADR 0092) is `pub(crate)`, so the overlay lives in `crates/ui`
  where the shared field is reachable instead of growing a second numeric widget in the shell. The
  shell projects the two anchors (`gizmo_math::screen_point`) and paints the guide lines.
- `Distances` is a pure scalar model (faces, walls, pins, locks, active side). It is tested without
  egui, so Tab/Enter/Escape, the lock reference, the midpoint, a missing neighbour and an impossible
  value are not behind a window.
- A press on a floating field is chrome, and the viewport response then reports no hover: the fill
  keeps measuring through the field (`DistanceFields` rects) or reuses the point the ghost was last
  measured at (`FillGizmo::measured_point`), so the fields do not vanish under the cursor.
- The plan order had V2 and V3 before N8; the owner asked for N8 first, so both were moved to
  `## Next` with `cargo xtask task defer`, the gated way to say their moment is later.

## Decisions

- The overlay is `crates/ui/src/distance.rs` and owns the field anatomy, the measurement model and
  the keyboard. The shell owns the geometry (product frame, ghost faces, screen anchors) and the
  single command; no new document field and no second probe (ADR 0103).
- `Side::Low`/`High` are the part's two thickness faces. A field's number is the distance from its
  reference face to the surface the niche found. Locking a side makes the opposite field measure
  from the locked face — a **span**, not a gap — which is what "the next distance is measured from
  the locked face" means.
- `place` keeps the part's extent (a fill's size is the void's), so a number on the side opposite a
  lock would resize it and is refused with `DistanceLockedFace`. `resize` is the box gesture's job
  (V2) and is not added speculatively.
- «По центру» clears the locks and pins both faces at the midpoint, so the pointer cannot pull the
  part out of the middle; Escape clears every pin and lock and returns the whole gesture to the
  pointer, and the overlay stays suspended until the maker clicks a field or the next part starts.
- The field nearest the pointer takes the keyboard without a click, so a number can be typed during
  a hover; exactly one field is active and the shared field's theme focus ring shows it.
- Enter locks the typed face; the click is still the one document write (`panel.create`), so a
  gesture is one undo entry. Escape is read by the overlay before the tool's own cancel: the first
  Escape returns the mouse, the next one leaves the tool (`handle_keys` skips while a field is
  active).
- The plates are clamped inside the viewport and their rectangles are excluded from picks, exactly
  like the command bar's rectangle.

## Ruled out

- A dialog or a command-bar row for the distances: the entry asks for a live field per direction and
  one active field, not a form (ADR 0103).
- A second numeric widget in the shell: the shared scrubbing field is the rule and the tests drive
  its unit-outside anatomy already.
- Resizing a filled part by typing the opposite span: a fill's size is the void's; a box that can
  resize is V2's gesture and will call the same `Distances` model.
- Rounding a typed gap to whole millimetres against a fractional wall: the number is whole and the
  wall keeps its micrometre precision, so the part stays flush (N6).
- Wiring the translate gizmo in this step: the drag commits on release inside `TranslateGizmo`, so a
  typed distance needs a pinned delta handed into `update` and an Enter that finishes the drag. That
  is a measured second step, not a guess inside this commit.

## Verification

`crates/ui/src/distance.rs`: the two gaps, a lock re-referencing the opposite field, typing moving
the part with its extent, the midpoint coordinate, a missing neighbour refusing, an impossible
value leaving the state untouched, a locked opposite face refusing a resize, Tab skipping a disabled
side, Escape clearing the pins, a sync keeping the pinned face, and an offscreen two-frame draw that
counts the two plates and the lock glyph's image. `apps/furnicraft/src/frame_tests.rs`:
`a_typed_distance_places_the_fill_exactly_and_the_click_creates_it` arms the shelf, types 120 into
the low field, proves no revision moved, proves the pinned ghost ignores the pointer, clicks the
scene at the pinned placement and proves one undo removes it. `cargo xtask ui-rules` is green with
the new host row. The typing feel was not driven in a live window in this session; the numbers,
focus and keys are covered headless.

## The move tool

- The translate drag already holds a `Drag { node, axis, rule, start_origin, start_delta, delta }` and
  commits on release, so the second consumer needed three facts and no new command: the drag's axis,
  its anchor and its delta. `TranslateGizmo` now exposes them, and `update` takes a `pinned` world
  distance that replaces the pointer for the frame. The release still runs one
  `node.placement.set_many`, so a typed move is the same undo entry as a dragged one.
- The measurement is the same probe: `Project::world_box` (the box the move rule already measures)
  gives the two faces, and `Project::probe` from one micrometre outside each face finds the first
  surface. `MoveDistances` snapshots the walls and the start faces when the drag starts, so the
  frame path re-probes nothing while the pointer travels.
- A floor-bound product has no free vertical distance (`MoveRule::allows`), so the fields are not
  offered on Z; the rule's own refusal and the field's absence say the same thing.
- The drag reads the pin one frame later: the frame that types sets the target face, the next
  `update` uses `pinned_low() - start_low` as the drag distance, and the fields follow that same
  number. The one-frame lag is invisible because the ghost and the field both show the pinned value
  before the next frame paints.
- Escape still belongs to the field while a pin stands: `update` leaves the drag alone then, the
  overlay clears the pin, and a second Escape leaves the drag. A field that vanishes hands the
  keyboard back (`DistanceFields::dismiss`), so shortcuts are not left behind a text focus nobody
  can see.
- A full-frame drag test was not written: driving the axis handle, the held button, the typed text
  and the release through `RawInput` repeats the pointer plumbing the existing gizmo has no test for
  either. The measured half — `document::tests::a_typed_move_distance_pins_the_gap_to_the_next_surface` —
  proves the walls, the 400 mm gap, the 300 mm pinned delta and the model test proves a floor-bound
  Z has no allowed distance. The drag feel is the live check that remains.
