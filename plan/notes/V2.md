# V2 — one box drawn with a base and a height, and its three sides edited in place

## What was measured

- `crates/model/src/primitive.rs` had `Cube { edge }` with a centred anchor and
  `Primitive::from_kind(kind, size)`; `crates/engine/src/object_cmds.rs` carried a `size` and a
  `PrimitiveKind` in `ObjectPrimitiveCreate`, so a caller could not name three sides. The card drew
  one field for it and the mesh builder borrowed `Mesh::cube` (the one centred box in the tree).
- `Mesh::cube` had exactly one production caller (the cube primitive) and eight test callers that
  used it as a solid around the origin. It is now `Mesh::cuboid(min, max)`; the centred fixture moved
  to `furnicraft_model::testing::cube_mesh`, re-exported by `furnicraft-testkit` (C7: one definition,
  because a crate's tests may not reach back into testkit).
- The drawing draft (`crates/ui/src/draw.rs`) is view state in the editor and the shell maps the
  pointer onto the work plane; the extrusion pull reads millimetres along an axis
  (`Ray::closest_parameter_on_line`). Both were reused rather than re-invented: `BoxDraft` is the
  same idea as `DrawDraft`, and `pulled_height` is the same axis read as `extrude_gizmo`.
- Grips had one existing shape in the tree, the panel/contour grip, and one existing undo rule, the
  session edit scope (`Session::edit_scope`/`dispatch_in`/`cancel_edit`, ADR 0092). The grips write
  live inside one scope, so a drag is one entry without a second preview path.
- A screen round trip costs about a pixel, which is ~3 mm at a 3 m camera distance. The creation
  gesture is exact because it maps the pointer onto a plane; the grip tests compare with a 5 mm
  tolerance and the corner/face mapping is asserted in whole millimetres.

## Decisions

- **The create command takes the parameter set, not a kind and an extent.** `ObjectPrimitiveCreate {
  parent, name, primitive: Primitive, placement }` matches `ObjectPrimitiveReplace`, so the box owns
  its drawn sides and a hostile params blob cannot smuggle an invalid size past serde.
- **The box is anchored at the base corner.** Its local zero is the drawn rectangle's minimum
  corner, so the placement the gesture commits is the plane frame translated there and the box
  occupies `[0..W] × [0..D] × [0..H]`. `Primitive::bounds_micrometres` now starts at `[0; 3]` for a
  box; cylinder and sphere stay centred.
- **The height pull is a pointer axis read plus a command bar.** The bar is the extrusion's bar with
  a `BoxHeight` label and the primitive bound; ✓ commits the same `finish_box` a click commits, so
  the typed and the dragged gesture cannot diverge.
- **The prism is shell paint, not the session overlay.** ADR 0093 keys an overlay entry by the id of
  a node the document holds, and the box does not exist before its one command — the same reasoning
  the empty-space ghost records (ADR 0104). The task's Shape said "through the session overlay"; the
  overlay's own rule wins, and ADR 0101 asks for the wireframe prism, which is what is drawn.
- **Ten grips: four base corners and six face centres.** A corner moves width and depth together
  (the rectangle the maker drew), a face one side. A corner projects the pointer onto the base
  plane; a face reads the pointer along the face's normal, so a face can be dragged from anywhere in
  the view and the bottom face can still be pulled down.
- **A minimum side moves the placement.** Growing a min face by `d` means the side becomes `s + d`
  and the origin moves `d` along the local axis, so the opposite face stays where it is in the world
  (ADR 0082/0088). Both commands run in the drag's scope, so undo returns the whole gesture.

## Ruled out

- **Creating the box at the base and previewing the height through the overlay.** It would give the
  overlay a real node id, but the gesture would be two commands (create, then replace) or a create
  that undo can see before the user accepted anything — exactly what ADR 0093 refuses.
- **One command that takes a placement beside the parameters for a min-face drag.** The edit scope
  already makes two commands one undo entry, and a `placement` field on `object.primitive.replace`
  would let any caller move a node without `node.placement.set`.
- **Reusing `DrawDraft` with `DrawTool::Rectangle` for the base.** The draft's commit is
  `object.path.create` and its "close" flow is a ring; the box needs the sides, not a path, and a
  second meaning for one draft would couple two tools that only share a rectangle preview.
- **Keeping `Mesh::cube`.** Two box builders with different anchors is the trap this task removes;
  the centred fixture is a test helper and now says so in its name.
- **A `cube` alias in the loader.** Schema 22's `cube { edge }` is refused outright; nothing is
  released (ADR 0096), so the bump to 23 has no migration and the golden file moved with it.

## Looked at

- `cargo test -p furnicraft --bin furnicraft -- --ignored` renders three offscreen shots on a GPU:
  the interface matrix, `box-tool.png` (the base, the pulled prism, its size label and the height
  bar) and `box-grips.png` (a selected box with its ten grips). The prism reads as a yellow
  wireframe over the shaded scene, the label sits at the pointer and the bar takes the bottom-centre
  slot with the cluster lifted clear.
