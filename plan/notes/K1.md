# K1 — what "the format has no past" still costs in this tree

## What was measured

- Nine goldens under `crates/project/tests/golden/` (`scene-v7`, `v8`, `v9`, `v10`, `v11`, `v12`,
  `v14`, `v18`, `v20`) and 20 tests in `crates/project/tests/scene_file.rs`, most of which assert a
  migration path rather than current behaviour.
- Two migration passes in `crates/model/src/project/wire.rs` (`migrate_machining_to_nominal`,
  `migrate_container_pivots`) plus the `1..=CURRENT` range in `ProjectWire::try_from`.
- The legacy acceptance is **not** in one place; it lives in six wire types:
  - `node.rs` — the `assembly` and `group` tags of schema 6, normalised on load;
  - `panel/mod.rs` — the v1 `size` field (`LegacyPanelSize`), the v14 top-level
    `corner_features`/`edge_bows`, and `alias = "pivot"` for v19;
  - `panel/machining.rs` — `MachiningWire::Legacy` and `LegacyCutout`, the tagged form of v15 and
    older;
  - `contour.rs` — a v10 point list and a v11 ring without segment ids;
  - `object.rs` — the v18 path without its shape tag (`untagged`);
  - `alias = "pivot"` again in `container.rs`, `camera.rs` (twice), `light.rs` (twice), `object.rs`.
- Errors that exist only for a migration: `ProjectError::MachiningCoordinateOverflow`,
  `PanelError::AmbiguousSize`, `AmbiguousOutlineFeatures`, `ContourWithFeatures`.
- `default_container_pivot` (`crates/model/src/tree.rs:185`) has one caller: the v5 pivot migration.
- Documents that describe the past: `docs/domain/scene-file.md` (the section pointing at
  `document.md` §8) and `docs/domain/document.md` §8.
- The current golden `scene-v20.fcs` is thin — a root and two primitives, no panel, no machining, no
  camera, no unknown section — so the tests borrow v8 for those, and the surviving golden has to be
  rebuilt rather than renamed.

## Decisions

- The schema stays at 20 here; T2 bumps it for the class rename (0094).
- One golden `scene.fcs` at the current schema, carrying what the nine carried between them: a panel
  with banding and machining, a contour with segment ids, a drawn path, a camera, a light, an active
  camera, a primitive, and an unknown top-level section.
- One error for any number but the current one: `UnsupportedSchemaVersion` for older and newer alike.
- The legacy branches go, not only the passes: a current file must not depend on a fallback field.

## Ruled out

- Renaming `scene-v20.fcs`: it exercises neither a panel nor an unknown section, so the surviving
  golden would protect almost nothing.
- Deleting only `wire.rs` and leaving the wire fallbacks: the same deserializer decides what a current
  file may contain, so the past would survive in the place that matters.

## Next

1. Build the new golden from the current serializer and check it in as `scene.fcs`.
2. Delete the two passes, the six wire fallbacks, the four migration-only errors and their tests.
3. Rewrite `scene_file.rs` around the one golden: load, round trip, unknown section, unknown field,
   any other schema number, atomic write.
4. Rewrite `document.md` §8 and `scene-file.md` to state the rule instead of the history.
