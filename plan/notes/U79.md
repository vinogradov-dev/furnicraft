# U79 — the skills are checked against the tree they describe

## What was measured

- `cargo xtask ci` ran fmt, clippy, tests, `layers`, `plan`, `docs`; nothing read `.pi/`. A renamed
  module left every `crates/...` path in a skill pointing at nothing, and the move to `.pi/skills`
  proved the loader was already fragile: pi parses frontmatter as strict YAML, and one unquoted `:`
  in a description loads no skill at all, silently.
- The check found three defects that were already in the tree: `references/human-factors.md` linked
  `../../../crates/ui/src/settings.rs`, one level short (from `references/` the root is four levels
  up); `.pi/prompts/*.md` carried an unquoted `description`; and `create-command/SKILL.md` named
  `docs/commands.md`, a file no task had created.
- `enforce-architecture/SKILL.md` was 208 lines against the 200 budget (the 150 budget for a
  reference is not close: 73, 84 and 42). The excess was a "Project status" section claiming M5
  while `plan/STATUS.md` says M7 A — a status line in a second home, which `AGENTS.md` forbids.

## Decisions

- `xtask/src/skills.rs`, in the shape of `state-contract/src/cli/docs.rs`: one `check(root, host)`
  returning the file count or a violation per mismatch, every sentence naming the offending file.
  `host` is `HOST`'s own names, so `cargo xtask skills` is checked like the rest.
- A **claim** is a backticked token or a markdown link that starts with a repository root (`apps`,
  `assets`, `crates`, `docs`, `plan`, `state-contract`, `vendor`, `xtask`, `.pi`) or with
  `references/`. A bare file name, a command id (`actions/delete`), an area (`contour/*`) and a
  `<placeholder>` are prose: checking them would need a symbol table, and a false positive here
  costs a session more than the rot it prevents.
- A backticked token resolves against the file, then the project root, then every skill directory,
  because `.pi/prompts/ui-review.md` cites `references/checklist.md` of the design skill. A **link**
  resolves only against the file: it is a real navigation, so its breakage is the reader's.
- `{a,b}` expands to its alternatives and `*` / `**/` match the tree. A single `*` covers
  `plan/*.md`; `**/` covers `AGENTS.md`'s `.pi/skills/**/*.md`; a `**` with a wildcard in the head
  (`crates/*/**/*.rs`) is refused rather than half-matched.
- `plan/SESSION.md` is in an `EPHEMERAL` list: it exists only while a task is live, so its absence
  from an idle tree is not rot. The list is the only exemption.
- The frontmatter rules apply to every scanned file that has frontmatter (`name` is the folder only
  for a `SKILL.md`, `description` is quoted and non-empty everywhere), so the two prompts were
  quoted in the same change.
- `cargo xtask skills` runs after `docs` in `ci`, and `the_real_tree_passes` runs the same check on
  the real tree from `cargo test`, so a renamed path fails both the gate and the test.

## Ruled out

- A `MISSING_OK` per path would have been a list of excuses; ephemerality is a property of one file,
  and the constant says which.
- Validating bare file names (`PROJECT.md`, `theme.rs`) needs the context of the sentence that names
  them (`theme.rs` means `crates/ui/src/theme.rs` in `surfaces.md`), which is the symbol table this
  check deliberately does not have.
- A regex crate for the extraction: the two scanners (`backticks`, `links`) are twenty lines and the
  dependency budget is not paid for them.
