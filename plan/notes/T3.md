# T3 — the inspector assigns a class from the tree, and a person can find the row

## What was measured

- `ClassRow` (`crates/model/src/class.rs` §3 of the doc) carried only code, slug, label, traits and
  hosts; the registry had no `aliases` and no `retired` field even though `docs/domain/classes.md` §3
  names both. `ClassCode::is_assignable` accepted any registered class row.
- The class property was drawn by the generic `PropertyValue::Class` arm of `edit_row`: a
  `TextEdit` whose hint was `GG.TT.VV`. The scene-tree component badge rendered `class.to_string()`,
  so a reader saw `[30.01.01]` and nothing said what it meant.
- `Properties::insert` already refused an unknown code or a family heading on assignment; loading
  kept an unknown number. The old text field therefore could not save a code the model refused, but
  it could offer nothing when a stored code was unknown, and it never said what the digits meant.
- The class property may be absent; `Project::class` reports `UNCLASSIFIED` for that and the card
  used to show the class only when the key existed.

## Decisions

- `ClassRow` gained `aliases` and `retired` with const builders (`with_aliases`, `retired`) and
  `is_assignable`; `ClassCode::is_assignable` now reads the row predicate. A row without aliases
  stays `&[]`, so the 65-row constructor calls did not change.
- Aliases are English and Russian search words taken from §7's prose (`shelf`, `полка`, `полочка`,
  `side`, `боковина`, `nightstand`, `тумба`, `bar`, `inset sink`, `gas hob`, …). They are searched,
  never displayed and never stored, so no document field changed and no schema bump was needed.
- The picker is one `Popup` in a new `crates/ui/src/class_picker.rs`; it is declared in
  `HOST_OWNERS` because it builds a host. The popup's width is 300 pt, a row 22 pt, a level 12 pt;
  the list scrolls at 320 pt. Family captions are not clickable because a family is never assigned.
- A query matches the label in both languages, the slug, an alias or the dotted code. A family or a
  type that matches brings its children, so `Хранение` or `cup hinge` shows the subtree instead of a
  dead end.
- Retired rows are filtered before the tree is built, so they are neither drawn nor assignable. The
  card still renders a stored retired code from `ClassRow::label`, which is the "still renders" half
  of the rule.
- Enter takes the first row a non-empty search leaves in registry order. It is deliberately not
  "the only match": `shelf` also matches `glass-shelf` and `shelf-pin`, and the horizontal panel is
  the broadest meaning, first in code order. An empty search does nothing on Enter.
- The property card draws a class row for every node, including a node that has no `class` key, and
  skips the reserved key in the generic loop. The row says `label   code`, or
  `code — not in the registry`; its tooltip is the same sentence because a long label truncates.
- Choosing a class, including the unclassified row, is one `node.property.set` with
  `SYSTEM_CLASS`; an explicit `class = 0` writes the sentinel instead of clearing the key. That keeps
  the assignment path unchanged and one undo returns the previous class.
- The scene-tree badge reads the label and keeps the code in a row tooltip; a component without a
  class keeps the `component` badge.

## Ruled out

- A `ComboBox`: it has no search field, closes on the first click and cannot draw a tree with
  captions; a popup with a field is the same amount of code and the one the palette already proves.
- A new `node.class.set` command: the reserved property is already validated by the model, and the
  task's rule is that assignment stays `node.property.set`; a second command would be a second path.
- A separate aliases table keyed by code: the doc says a row carries its aliases, and two tables
  drift; the builder keeps the words beside the row.
- A retired row in the shipped registry: no code has shipped before 1.0, so a withdrawal is a future
  event. The flag is exercised with a synthetic row in the model and picker tests.
- A pixel shot: the picker only uses `theme` tokens and introduces no new colour, contrast or
  translucency question. It was checked headless with an `egui::Context` (drawn texts, the filtered
  tree, the selected current row, Escape and the one-undo assignment); no offscreen PNG was needed
  for this task, and `apps/furnicraft/src/ui_shots.rs` still covers the look matrix.
