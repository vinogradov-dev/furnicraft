# T4 — what a class forbids is what the editor refuses

what a class forbids is what the editor refuses

## What was measured

- After T2 the registry held 65 class rows and a `TraitSet`, and after T3 the inspector could assign
  one; no code path read a trait. The class table was documentation.
- The decisions live in four places: `panel.resize` (`crates/engine/src/panel_cmds/panel.rs`),
  `mesh.vertices.move` (`crates/engine/src/mesh_cmds.rs`), the banding/corner/bow setters
  (`panel_cmds/banding.rs`), the machining add/update (`panel_cmds/machining.rs`) and the class
  assignment (`crates/engine/src/node_cmds.rs`).
- There is no scale gizmo: the vertex gizmo (`apps/furnicraft/src/vertex_gizmo.rs`) is the only gizmo
  that edits a node's geometry, so it is the one that offers resize-like handles.
- The panel card drew length and width fields for every panel and a banding, shape and machining
  section for every panel, whatever its class.

## Decisions

- `crates/engine/src/class_rules.rs` holds the one accessor: `NodeRules` (`extent`, `admits`,
  `nesting`, `measure`, `may_sit_in`, `allow_*`), a typed `ClassRefusal`, and the local `Dimension`
  axis pair (X length, Y width, Z thickness). Commands read it; no command compares a code.
- A node with no class — or a code the registry lost — has no rule, so every gate is open. That keeps
  an ordinary scene editable before a maker assigns a class and is the same reading the cutting list
  will take (`nesting`/`measure` return `None`).
- Every gate runs in both `enabled` and `run`: dispatch bypasses `enabled`, so an `enabled`-only rule
  would be a suggestion.
- `panel.resize` compares the requested length and width with the current size. A no-op resize is
  allowed (a field that reports the current size must not fail); `LengthOnly` refuses a width change,
  `None` refuses any change. `mesh.vertices.move` compares each new position with the stored one per
  axis, so a move that leaves a fixed axis alone is not an edit on it.
- Banding, corner-banding and ring-banding setters read `Operation::EdgeBand`; the outline, bake,
  corner and bow setters read `Contour`; machining add/update read `operation_of(kind)` so a new
  machining kind is a compile error in one place. The matching clears stay allowed: taking a trim or
  a feature off never contradicts a class, and a hostile file may hold one the row never admitted.
- `host` is checked when a class is assigned (`node.property.set` / `set_many`): the class arrives
  after the node, so that is the first moment the host rule is checkable. An unclassified or unknown
  host never refuses, and an unclassified object claims nothing.
- The panel card disables the fixed size field and says why with a message; the banding and shape
  sections and the machining add menu are replaced by a sentence when the class forbids them. The
  vertex gizmo filters its handles through `editable_axes`, the same accessor.
- `docs/domain/classes.md` §12 settles the host question: a code prefix is the rule, and a row that
  must refuse a sibling narrows its prefix.

## Ruled out

- A gate only in `enabled`: `Session::dispatch` calls `run` directly, so the document would still
  change.
- Refusing a no-op resize: the card reports the current size and would fail on itself; the model
  still validates the geometry and the machining.
- A second accessor for the gizmo: `NodeRules::may_resize(axis.dimension())` is already the answer,
  and a gizmo-local copy would drift.
- Gating the clears: removing a band or a corner feature never contradicts the class.
- Checking `host` on placement or reparent: no command currently changes a classed node's parent, so
  the check would be unreachable; the gap is in `plan/debt.md` for the command that does.
- A `ProjectError` variant: the gate is editor policy, not a document invariant, so it is a
  `CommandError::ClassRefused` with a typed reason.
- Translating the refusal in the message table: `plan/debt.md` already records that engine sentences
  reach the status bar in English; the card names the same rules in its own messages instead.
