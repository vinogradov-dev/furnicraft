# U82 — the editor opens an empty scene

## What was measured

- The launch path had exactly one production caller of the demonstration document:
  `apps/furnicraft/src/main.rs:214`, `FurniCraftApp::new` → `Self::build(…, sample_session()?)`. The
  other three call sites — `document.rs`'s two tests, `frame_tests.rs`'s harness and
  `ui_shots.rs`'s shot builder — are all `#[cfg(test)]` modules.
- `apps/furnicraft/src/scene_build.rs` held the whole demonstration document in one function: three
  panels (a back panel, a shelf, a drawer front), three cutouts, three bands, one group, one
  component, the root named `"FurniCraft sample"`, the four ids of its materials and the helpers
  `add_band`, `panel_nominal_size`, `rectangle` and `cutout`. Those four helpers had no other caller.
- `empty_session()` already existed and was what *New* (`main.rs:387`) and the close of the last tab
  (`main.rs:466`) used, so the shell could already open, save and draw a document with nothing in it;
  only the launch took the long way round.
- The catalogue (`PanelMaterial`s and `EdgeBandingMaterial`s) is not scene data: it is never written
  to the file and a new document carries it whatever the file holds. Removing the demonstration
  *objects* therefore does not remove the materials a maker creates a panel from.

## Decisions

- **The demonstration document stays as a test fixture, not as a second empty scene.**
  `sample_session` became `#[cfg(test)] demo_session()` with a doc comment that says it is a fixture:
  the evaluation tests, the frame harness and the offscreen shots need a document with a panel, a
  band, a cutout, a group and a component in it, and deleting it would delete the only coverage of
  the evaluation pipeline. Its helper functions carry the same `#[cfg(test)]`, so the binary build
  does not carry code nothing calls.
- **`initial_session()` is the seam the launcher calls.** The guard test asserts what the window
  opens with, not `empty_session()` on its own: a later change to `FurniCraftApp::new` that puts a
  demonstration scene back has to go through this function, and the test fails there.
- **`sample_catalog()` became `default_catalog()`, and its ids `DEFAULT_*`.** The catalogue is the
  workspace's, not a sample: a new document offers those materials because a panel cannot be created
  without one, and the old name would suggest the whole thing is demo data to be removed later.
- **The demo root is called `Demo`.** It was `"FurniCraft sample"`, one of the hardcoded product-name
  copies task R1 lists; the fixture no longer names the product at all.

## Ruled out

- **Deleting `demo_session` and pointing the tests at `furnicraft_testkit::sample_project`.** The
  testkit fixture has no cutout, no band, no component and no drawer; the evaluation, banding,
  shadow and picking tests would each have to rebuild their own document, and the demo document is
  exactly the case where one fixture serves them all.
- **Keeping `sample_session` public with `#[allow(dead_code)]`.** A production symbol that only a
  test calls is exactly the mistake this task undoes; the `cfg` says what the function is.
- **Renaming `sample_session` to a private test-module function.** `document.rs`, `frame_tests.rs`
  and `ui_shots.rs` build their sessions from it, so it has to stay visible to the crate's tests.
