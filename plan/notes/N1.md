# N1 — a product is a container with a product class and an authored envelope

N1 — a product is a container with a product class and an authored envelope

## What was measured

- ADR 0097 settled the entity before this task: no new node kind, `Envelope` on `Container`,
  `level = Product` as the role, and the model refusing both mismatches. The registry already had
  the `80.01.00` general-product row (`crates/model/src/class.rs`), so the placeholder needed a
  `ClassCode` constant, not a new row.
- `cargo xtask task N1` listed three files, but the model's command families already live one per
  module (`project/{panel,object,node,camera_light,property}_cmds.rs`), so both the model operation
  and the engine command got a `product_cmds.rs`; the `files:` hint was updated through
  `cargo xtask task set N1 --field files`.
- The tree invariants were checked in exactly one place before this task: `scan_tree`
  (`crates/model/src/project/mod.rs`) ran on load and on `Project::validate`; every mutator
  validated separately. The class write path was `Project::set_properties` / `clear_property` in
  `project/property_cmds.rs`, with no knowledge of a container's payload.
- Four engine diagnostics fixtures and the golden scene carried the schema number as a literal.

## Decisions

- `Envelope` lives beside `Container` in `crates/model/src/container.rs`: three `Length` sides named
  `x`, `y`, `z` after the product frame, a `TryFrom<EnvelopeWire>` so a hostile file gets the same
  typed `EnvelopeError` as a caller, and a 10 m side ceiling matching the panel limit. `Length` is
  integer micrometres, so "finite" is the type, not a check.
- The class is the definition: `Container::is_product()` asks `ClassCode::is_product_class()`, and
  the envelope is the box. `ClassCode::GENERAL_PRODUCT` is a named constant for `80.01.00`, with a
  test that it is that registry row and carries `level = Product`.
- `Project::add_product` is the one creation path: one revision, one allocated id, the class and the
  box written before the container enters the tree, and `product_of(parent).is_some()` refuses a
  nested product. `product.create` resolves the placeholder and validates the name; the model
  re-checks the class even though `enabled` already did.
- `validate_class_change` in `project/product_cmds.rs` is shared by `set_properties` and
  `clear_property`, so the pairing and the nesting rule hold for property edits too. A product's
  class may change to another product class; promoting a group via `node.property.set` is refused
  because "nothing else may create a product".
- `scan_tree` validates the pairing, the root-is-not-a-product rule and the no-nested-product rule,
  so a hostile file is a readable `ProjectError`, never a half-valid document.
- `product_of` climbs parents at most to the depth limit and answers with the nearest product at or
  above the node; `products()` is one bounded depth-first walk in tree order. Neither is stored.
- Duplicating clones the container, so the envelope comes along; `convert_to_group` clears it in
  `clear_component_marker`, which already cleared the class and the prototype keys.
- Schema `21 → 22`; the golden file was regenerated and the four diagnostics fixtures updated, with
  no migration and no alias (ADR 0096).

## Ruled out

- A `Node::Product` variant or a second container type: ADR 0097, and every lookup in `tree.rs`
  would have learned a new arm.
- Storing `parent_id` / `product_id`: both are derived and would go stale; the climb is bounded by
  `MAX_ASSEMBLY_DEPTH`.
- Deriving the envelope from the children: it is authored before any part exists and a child that
  pokes out is a diagnostic (N2+), not a resize.
- Allowing `node.property.set` to make a product: the envelope has no second authoring path, so the
  class would arrive without its box; the refusal is the invariant, not a policy gate.
- Letting the root be a product: the root defines the world frame, so a hostile file is refused with
  `RootIsAProduct` rather than accepted as a product with an envelope.
- Reusing `frame` in code for the box: the tree already has four frames; ADR 0097 names the field
  `Envelope` and leaves «Каркас изделия» to the interface.
- A UI path in this task: the class picker can assign a product class only to an existing product
  (which has a box), and the frame card/gesture is V3/N2; N1 stops at the model and the commands.
