# N4 — the creation guard lives in the command, and the session asks it last

N4 — the creation guard lives in the command, and the session asks it last

## What was measured

- `CommandSpec::run` (`crates/engine/src/commands.rs`) received `&mut Project, &Catalog, &Value` and
  no `Session`, so a command could not read `active_product` while it ran. Altogether 54 `*_run`
  functions share that signature.
- `Session::dispatch` (`crates/engine/src/session.rs`) never consulted `CommandSpec::enabled`; it
  cloned the document, ran the command and installed the copy. A disabled command therefore wrote
  unless its own `run` refused.
- `panel.create` and `panel.contour.create` were the only commands that create a panel today; there
  is no facade or fitting creation command in this tree, so the gate is declared by the two panel
  commands and awaits its next caller.
- `sample_project()` (`crates/model/src/testing.rs`) has 254 call sites across the workspace, and
  model tests may not use `Session`, so growing that fixture would have been a wide, typing-only
  change.
- `Message` rows are `Variant = [English, Russian]`; `ClassRefusal` still prints English through
  `Display` until the engine message mapping lands (`plan/debt.md`, `[ui]`).

## Decisions

- `class_rules` now owns `CreationRefusal` (two variants), `is_furniture(Level)` and
  `allow_creation(project, parent, open)`, the same shape as the existing class gates: the target's
  `product_of` must be the open product.
- `CommandSpec` carries an optional `Creation { level, parent_of }`. A furniture command declares it
  with `.creating(Creation::new(Level::Part, created_parent))`, so the guard reads the class level
  rather than a command id.
- `Session::run` asks `creation_refusal` **after** the command ran on the copy and **before** the copy
  replaces the document. A refusal therefore writes nothing and records no history, while malformed
  parameters still return the command's own `InvalidParams` (the order the existing tests expect).
- The command's `enabled` check calls `allow_creation` directly, so the palette and any caller of
  `CommandSpec::enabled` refuse for the same reason the dispatch does.
- Two messages name the two refusals: «Сначала создайте изделие.» and
  «Изделие закрыто; откройте его, прежде чем добавлять деталь.» The error prints the English text;
  the table is ready for the language switch.
- The testkit fixture is a new `sample_product_project()` (the sample scene plus product id 5 with the
  placeholder class and a 600 x 560 x 720 mm envelope). Engine tests open it through a local
  `product_session()`, and `panel_create` targets the open product when one is open. A primitive test
  asserts `active_product() == None` and still creates.
- UI tests that created a panel at the root now either open a product first or assert the refusal;
  the "every creation tool lands at the root" test kept its free tools and moved its panel case into
  its own refusal test.

## Ruled out

- Adding `active_product` to all 54 run signatures: a large mechanical edit in files the task does
  not own, and it would put the guard before the commands' own parameter validation.
- Making `Session::dispatch` call `enabled` first: it would replace precise errors such as
  `InvalidParams` and `ContainerNotFound` with a generic "disabled", and `enabled` is an advisory
  predicate, not a parser.
- Changing `sample_project()` to contain a product: 254 call sites, many asserting ids, child counts
  and tree paths; the new fixture costs nothing and keeps the guard's change to the part tests.
- A hard-coded list of command ids in `Session`: the guard would drift from the command it belongs
  to and would not travel with a future facade or fitting command.
- Gating primitives, drawn figures, mesh objects and hardware models: ADR 0098 keeps free modelling
  free, and only a Part or a Fitting is furniture.
