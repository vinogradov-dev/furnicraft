# T1 — the class table, and why each row exists

## What was measured

- `docs/domain/classes.md` (177 lines before this task) defined the mechanism — encoding, traits,
  the rules for earning a code — but had no rows: §10 called the full table "a design artefact of its
  own".
- The old registry in `docs/domain/furntypes.md` (210 lines) classifies by the *role* an object plays
  (10 product, 20 part, 30 facade, 40 hardware); ADR 0094 removed that axis and gave the top level to
  the function family.
- Two codes were already pinned by accepted records: `30.01.02` is a wall cabinet and `40.01.01` a
  work table (ADR 0097), so the cabinet type is `30.01` with mounting variants, and the table type is
  `40.01`.
- `docs/domain/classes.md` §5 and §8 used codes that no longer fit the new groups (`60.01.01`
  worktop, `60.02.01` plinth, `50.01.02.01` — a fourth level, which the encoding forbids). All are
  corrected in the same change; appliances take `60`, boards and trim take `70`.
- `docs/domain/products.md` §7 names exactly two fills in version 1 — a post takes height and depth,
  a shelf takes width and depth — and says a drawer, a back panel and a facade need their own rules
  later. The table therefore gives a fill to `30.11` and `30.15` only.

## Decisions

- **Supply gains a fourth value, `MadeInShop`** (ADR 0104): none of sheet, linear or piece describes a
  product, and forcing a cabinet into `MadeFromSheet` would derive `measure = area` and
  `nesting = member`, i.e. a whole cabinet in a cutting plan.
- **Hinges: two types, three variants each.** The mounting form (overlay, inset, half-overlay) is the
  variant axis; card versus cup hinge is the type axis, because a fourth level does not exist and the
  cup hinge's bore is a real difference. A damper is an article, not a class.
- **Doors: one type, three variants** (hinged, sliding, lift-up), because the machining rule differs —
  cup bore and mounting pattern, groove, pattern. A drawer front is a second type: its report line is
  its own and no machining rule separates it from a flap.
- **Products:** cabinet with three mounting variants; wardrobe and chest as types (report line only).
  Seating, lying and surfaces exist at level `Product` only; their parts arrive with their tools,
  because a part row earns its code when a report names it and a tool creates it.
- **Storage parts** keep `side`, `shelf`, `bottom`, `top`, `back`, `divider`, `drawer box part` as
  seven classes: `fill` separates the vertical from the horizontal, `ops` separates the back (no edge
  banding), and the parts list and the assembly drawing name the rest apart.
- **The placeholder is `80.01`**, the only class of the family `80` «Общее», «Изделие общего
  назначения»; it has no function, so putting it in a real family would make that family's report
  line lie. `90` stays reserved for a workshop's own family and `TT = 90..99` inside every family for
  its local codes.
- **A family is a heading, not a class.** `GG.00.00` carries a slug and a label but no traits: the
  members of `30` disagree about `supply` (parts are sheet, products are assembled, a glass shelf is
  bought), so no trait set is true of the family and inheritance has nothing to narrow. Every table
  row is a type or a variant, and §3 says so.
- **Appliances are components, not products** (level `Component`, supply `piece`): they are bought
  whole, acquire no parts and carry no envelope, so they need no `mount`. That also avoids inventing
  a third mount value for a built-in oven.

## Ruled out

- **A code group for products** (the old `10`): 0094 removed the role axis; a product is a class
  trait (`level = Product`), not a range.
- **A `BuiltIn` mount value**: an appliance is not a product, so the question does not arise; adding
  the value would have needed a second consumer that does not exist.
- **One `panel` class with aliases** for side, shelf, bottom, top: a query for "every shelf" would
  return bottoms, and the assembly drawing names them apart.
- **Separate rows for variant features with no rule behind them** — a damper, a bar versus a knob
  handle, a gas versus induction hob, a straight versus L-shaped worktop: aliases, not codes.
- **A row per seating or table part**: no tool in this milestone creates one; the rows land with the
  tools, as §6.1 says.

## Remaining for the owner

The table is written and awaits approval row by row. The four decisions that are genuinely the
owner's are the `MadeInShop` value, the cabinet/wardrobe/chest split by report line, the door
type-plus-variants shape, and the placeholder's home in family `80`.
