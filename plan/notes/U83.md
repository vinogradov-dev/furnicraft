# U83 — one guide ink and one stroke rule

## What was measured

- `crates/ui/src/theme.rs` — `Palette`/`Ramp`: `warn` is `#d8a43c` in all three dark ramps and
  `#8a5a0f` in all three light ramps. It is the only ink besides `danger` that does not differ by
  preset, and `with_accent` never touches it, so a derivation from it lands on one value per variant.
- `crates/ui/src/theme.rs` — `Palette::readable` already pushes a colour towards white on a dark
  palette and black on a light one; the guide ink reuses that direction instead of a second rule.
- `crates/scene/src/lib.rs` — `SceneColors` is a plain const pair (`DARK`, `LIGHT`) keyed by the
  `egui::Theme`, and `document.rs:138` copies it into a built frame with `apply_colors`; the shell
  re-reads `theme::scene_colors(ctx.theme())` once per frame (`main.rs` 266, 687, 734). The scene
  cannot see the palette, so the value has to be a constant on that side and a derivation on this one.
- Contrast of the chosen ink, measured with `contrast_ratio` (WCAG, 1..21):

  | variant | ink | header | panel | workspace |
  |---|---|---|---|---|
  | dark | `#e2bb6d` | 9.21 | 8.27 | 9.39 |
  | light | `#68440b` | 7.73 | 8.16 | 6.57 |

  The accent (`#e0a24a` / `#a6620f` by preset), the danger ink and `SELECTION_LINE_COLOR` are all
  distinct from both.

## Decisions

- The ink is `mix(warn, white if dark else black, 25)` — a quarter away from the surface, which is
  the one direction `readable` uses. On slate it is brighter than a warning, on paper it is deeper:
  a guide is adjacent to a warning but is not one, and the value says so without leaving the hue.
- Three widths in points, not a size per guide: `HELPER_CROSSHAIR_STROKE` 1, `HELPER_STROKE` 1.5,
  `HELPER_OPEN_STROKE` 2. The bracket of the open level is the heaviest because opening a level is
  what decides the next click.
- The scene carries the same colour as `SceneColors::helper` (and `SceneFrame::helper` through
  `Default`/`apply_colors`), written as `u8 / 255.0` so the `ui` test can compare exactly instead of
  with a rounding tolerance.
- `theme::helper(ui)` reads the installed `Visuals` (`warn_fg_color`, `dark_mode`) like every other
  accessor, and `Palette::helper()` is the same rule for a palette: the test drives a real frame for
  all six palettes, so a fallback to `DARK` would fail in the light variant.

## Ruled out

- **Deriving from `accent`.** `InkAzure` and `SlateMint` accents are blue and mint, so any mix pulls
  the amber to khaki or green; the ink would stop being warm by preset.
- **Deriving from `text`.** It differs per preset by 1–2 units, so no single `SceneColors` constant
  could be equal to the chrome ink; a tolerance would hide which side drifted.
- **A hand-picked value per `Ramp`.** A twelfth token per variant, contrast checked by hand, and the
  scene literal would be a second owner of the same number.
- **Lifting to a contrast floor** (the `readable` loop) — `warn` already measures 3:1 or better on
  the surface, the panel and the workspace in every variant, so the loop never fires. A rule whose
  effect is never exercised is not a rule; the fixed lift is measurable in the test instead.
- **Making the ink preset-aware.** The workspace colours are deliberately not preset data (ADR 0087),
  so the frame has no place for a per-preset guide ink without a second bridge from chrome to frame.
