# U81 — the interface renders offscreen, so the look matrix is a folder of pictures

## What was measured

- `egui_wgpu::RenderState::create` takes `compatible_surface: None` and documents headless use
  ("offscreen rendering, tests, compute-only workloads"), so the shot needs no window, no surface
  and no display handle — only an adapter. `RenderState`'s fields are all public, but `create` also
  picks the target format (`Rgba8Unorm` when there is no surface) and builds the renderer the
  scene's `register_native_texture` talks to.
- On the owner's machine `Instance::default()` finds two adapters (Vulkan Intel ADL GT2 and GL), so
  the shot is verifiable here; the code path for a machine with none is a sentence and a return.
- `eframe::App` is only a window; the whole frame is `FurniCraftApp::frame(ui)`, and a `Document`
  with a `RenderState` creates its own target, registers the colour view with the shared renderer
  and draws it through `Painter::image`. Nothing in `crates/render` or `crates/ui/src/theme.rs` had
  to change: the picture is the egui pass, and the renderer's own target is only sampled by it.
- A shot of 72 cells takes 11 s and 18 MB: the 200 % cells are 2560 × 1680.
- The launch view fits the whole scene, so at 1280 pt the fitted model spans about 365 px and does
  not reach either floating panel: the checklist's "a panel over the model" was not answerable from
  the default framing.
- `TexturesDelta` asserts on drop that its deltas were applied, and `set` is a map to a list of
  `ImageDelta` per texture — the font atlas grows over the frames that settle the shot.

## Decisions

- The shot paints with the app's own `egui_wgpu::Renderer` from the render state the app was built
  with, so the scene texture, the glyph atlas and the shapes go through exactly the path a window
  uses; only the final target is a texture instead of a surface.
- `RendererOptions::PREDICTABLE`: no dithering and no texture filtering tricks, because a picture
  that is judged by eye should not carry noise the window would add.
- Three frames per cell, and every frame's texture deltas are uploaded while only the last frame's
  shapes are painted: the atlas is incremental, the layout is not (U78's sizing pass).
- `SETTLE_FRAMES`, the opacities and the scales read their values from `settings` and `ui_scale`
  (`MIN`/`DEFAULT`/`MAX_PANEL_OPACITY`, 100 and `MAX_PERCENT`), so the matrix follows a change to
  the control instead of guessing a number.
- The file name is the cell: `<preset>-<variant>-opacity<N>-<expanded|folded>-scale<N>.png`, using
  the names the workspace file stores, so a picture and the workspace that would draw it agree.
- The shot zooms the active view by 2.5 (`Document::zoom_active_view`, `#[cfg(test)]`) because the
  translucency question is about a panel *over the model*; the zoom is the same view state a wheel
  gesture writes, and at 2.5 the model runs under both panels by about 40 px each side.
- The render target is handed back after each cell (`Document::release_target`, which `release` now
  calls). A registered native texture outlives the document, and 72 cells would otherwise hold 72
  scene textures in the window's renderer.
- The PNG writer and the shots directory live in `furnicraft-testkit` (`write_png`, `ui_shots_dir`):
  a test-only crate is the place for a test-only output format, and `target/ui-shots` honours
  `CARGO_TARGET_DIR`.
- The test is `#[ignore]`, so `cargo test` and `cargo xtask ci` never touch a GPU. It still prints
  one sentence and returns when there is no adapter, so `--ignored` on a machine without one passes.
- One assertion beyond "every file was written": the 55 % and the 100 % cell of one look reach more
  than a thousand different pixels, and no picture is a single flat colour. Contrast, washout and
  whether the model reads through the fill stay for the person looking — the task's rule.

## Ruled out

- `egui_wgpu`'s `capture` module: the feature is not enabled by `eframe`, so using it means adding a
  direct `egui-wgpu` dependency whose features must agree with `eframe`'s for the target format and
  the device types; the forty lines here are smaller than that coupling.
- A second device per shot: 72 pipeline compilations for no isolation the release above and a fresh
  `egui::Context` do not already give.
- Comparing the pictures pixel for pixel in CI: they depend on the GPU's rasteriser, and the task
  says the pictures are looked at.
- A BMP or PPM writer to avoid a dependency: `png` 0.18 is already compiled into the tree through
  `epaint` (and `pollster` through `eframe`), so both are dependency edges and no new build.
- Rendering the scene's own target and writing *that*: it has no chrome, no panel and no text, so it
  cannot answer a question about translucency, contrast or scale.
- Reading the rects instead of the pixels: the whole task exists because rects cannot show a colour.
