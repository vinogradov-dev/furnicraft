# M72 — the last numeric text edits in the inspector

The figure card, the primitive card and a typed `Length`/`Angle` property were the three places U65
(ADR 0092) left behind: an ad-hoc `TextEdit` of ~100 px with the unit inside the buffer, a hint line,
and an Apply button. ADR 0092 names this task as its only remaining gap.

## What was measured

- `object_card.rs` (1034 lines before the change): `length_field`, `count_field` and `angle_field`
  drew `TextEdit::singleline(..).desired_width(100.0)`; the fields held `String`s read through
  `Length::to_string()` / `Degrees::to_string()`, so the buffer was `"100 mm"` / `"90°"` — the unit
  was selectable and a pasted number had to survive a suffix.
- `properties_card.rs`: `Length` and `Angle` rows were a `TextEdit` of 120/100 px, committing on
  `lost_focus()` and re-parsing the text; `Integer` already used `Scrub` but read `.changed()`, so a
  drag dispatched one command per frame — one undo entry per frame, which U65's edit scope exists to
  prevent.
- `Scrub::show` allocates its id from `Ui::allocate_space`, i.e. positionally. A property row moves
  when another property is added or removed, so the value a field edits cannot be positional.

## Decisions

- **The draft is numeric, in the field's unit.** `FigureFields`/`PrimitiveFields` hold `f64`
  millimetres and degrees and `u32` counts; the card converts to `Length`/`Degrees` once in `parse`,
  at the command edge. Typed text is parsed by `scrub::parse_millimetres`/`parse_degrees`, so the
  document's own precision rule still applies and the unit is outside the buffer.
- **Geometry parameters commit on release.** A figure or primitive parameter re-cuts geometry and
  rebuilds a mesh, so `CommitPolicy::OnRelease`: the box shows the dragged number, the document takes
  it once; typed text waits for the existing 150 ms debounce. The property numbers, being metadata,
  stay `Live`.
- **One section, one dispatch, one scope.** A section draws its fields, folds their `FieldOutcome`s
  into a `FieldReport`, and the card parses once and dispatches once after drawing, through
  `Session::dispatch_in(scope, …)`. The scope the field minted is the one the commit carries, so one
  drag is one undo entry and Escape restores through `Session::cancel_edit`.
- **A property number is keyed by its name.** `Drafts { text, numbers }` replaces the one string map;
  `NumberDraft` keeps the field value and the `PropertyValue` it was read from, and re-reads on a
  mismatch (undo, another card). That makes the value follow the property rather than the row.
- **ApplyFigure, the primitive Apply, PrimitiveEditHint and the five text-parse messages are gone.**
  `Message::Apply` stays: the status bar still draws it.

## Ruled out

- **Letting the section dispatch per field while it draws.** camera_card/light_card take a snapshot
  and dispatch after the section; the object card already returned early on an Apply, and keeping the
  parse central means one revision and one undo entry per frame even if two fields report a commit.
- **Refusing `0` instead of clamping.** The shared field's contract is "parse, clamp to the offered
  range, mark red only on text it cannot read"; the figure/primitive range starts at the model's
  minimum (`MIN_PRIMITIVE_SIZE`, a positive length), so a typed `0` lands on the nearest settable
  value. The model still refuses what the setter cannot build, and the card reports it.
- **A per-row `session.edit_scope()`.** The per-frame token separates two gestures by construction
  (a drag keeps the token of the frame it started in), which is the pattern camera_card and light_card
  already use.
