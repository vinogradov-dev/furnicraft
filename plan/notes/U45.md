# U45 — What was measured

## What was measured

- `apps/furnicraft/src/main.rs` before the split: 2037 production lines, one `impl FurniCraftApp`
  with 40 fields and 113 functions, `viewport` 635 lines, `adopt` (the one way a second scene could
  have replaced the first) 42 lines, `file_menu.rs` 329 lines carrying `dirty` through nine
  signatures only for the New question. S7 measured the same shape as finding F1.
- After: `main.rs` 696 lines total (≈455 production), `document.rs` 2001 (≈1740 with the tests and
  the five free functions it took), `tabs.rs` 388 (≈200 with its tests), `header.rs` 310,
  `file_menu.rs` 420, `status_bar.rs` 426.
- The old `FileMenu` asked a question in nine places: `show(ui, dirty)`, `show_dialogs(ctx, dirty)`,
  `save(dirty)`, `new_scene(dirty)`, `command(cmd, dirty)` and the dialog's yellow warning. None of
  them survives: opening a tab discards nothing.
- `Layout::reset_cameras` and `LayoutState::reset_cameras` existed only for `adopt`: they refitted
  every remembered layout on a new scene. They had two tests of their own.

## Decisions

- `Tabs` keeps the first tab in its own field and the rest in a `Vec`, so `active()` is total: the
  alternative was `Option` on nine call sites or an unwrap, and both read worse than a struct field
  whose existence is the invariant.
- `ViewportRenderer` and `TextureId` are per document; `egui_wgpu::RenderState` is cloned into each
  (it is a set of reference-counted handles), so a tab draws into its own texture and a close hands
  it back through `Renderer::free_texture`.
- The display switches (`all_edges`, the grid, the contact shadow) stay window state and are pushed
  onto the active document once a frame, because a frame rebuilt by a command outside the viewport
  (a card, a shortcut, the status bar) must draw what the viewport shows. Storing them per document
  instead would let a tab disagree with the cluster that drew it.
- `preview()` asks both gizmos for a live drag instead of reading the transform mode, so the mode can
  stay on `Shell` and the frame still follows the drag that is actually live.
- `sync_scene` split into the shell-facing entry (stores the display state) and `refresh` (revision
  check, evaluate, upload); every mutating path calls `refresh` and needs no window parameters.
- The last close replaces the payload instead of removing the tab: `CloseOutcome::LastTab` tells the
  shell to build an empty document, which keeps `Tabs` non-empty by construction.
- *New* and *Open* open tabs, so the File menu lost its `dirty` parameter entirely and the close
  question became `ConfirmClose`, owned by the shell. `Ctrl+N` and `Ctrl+W` joined the shortcut table
  so the header's tooltip is not a lie.

## Ruled out

- Making `Tabs` generic over a document *trait* so tests could build a headless document: the GPU
  parts (renderer, texture) are the whole reason a document needs a window, and a trait would have
  meant faking them in every test. The tab rules are tested on a payload that carries exactly the
  four things a tab must keep apart (path, history, selection, camera).
- A `HashMap<TabId, Document>` with a separate order vector: two structures to keep in step for no
  gain, and no total `active()` either.
- One render target shared by every tab with a per-tab swap: the renderer caches pipelines and
  buffers per frame, so a swap would have cost a re-upload of the whole scene on every tab switch.
- Keeping the split layout on the window so a new tab inherits it: the cameras are what the split
  holds, and they are the scene's, so the layout is the tab's (ADR 0086, superseding ADR 0079's
  refit-on-open clause).
