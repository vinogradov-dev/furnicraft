# M71 — a previewing operation gets a command bar, and a slow rebuild says so

## What was measured

- `apps/furnicraft/src/extrude_gizmo.rs` wrote the height on every drag release
  (`ExtrudeEvent::Set` → `object.extrude.height.set`) and kept its own Enter/Escape popup with a
  `TextEdit` at 84 pt, while `plan/notes/U65.md` already fixed the field anatomy at 76 pt with the
  unit outside. The two surfaces could not agree on a commit policy.
- The pull's preview was a wireframe prism drawn by the egui painter (`ghost_edges`): the solid the
  user was about to accept was never on screen.
- The ribbon's boolean tools are `planned` in `crates/ui/src/toolbars/spec.rs` and there is no
  boolean command in `crates/engine`, so "extrude and boolean" has one operation to preview today.
- `Document::refresh` compared the document revision and the editor's visibility revision only, so a
  frame built from anything else — a preview — had no way to be invalidated.
- `shell.rebuilding` was computed one frame ahead (`rebuild_pending`) but painted on the same frame as
  the work, so «Перестроение…» appeared after the rebuild it described, on every rebuild, however
  cheap.
- `Session` had no preview concept at all: `preview` in the shell (`gizmo_math::Preview`) holds
  *placements* for the move and rotate gizmos, not geometry, and lives outside the engine.

## Decisions

- The overlay is engine state (`crates/engine/src/preview.rs`, ADR 0093): a node id → `Geometry` map
  with a version, set and cleared through `Session`, touching no revision, no history and no file.
  The shell compares the version with the one its frame was built from, so a preview costs exactly
  one rebuild and nothing else.
- `EvaluationCache::object_with(revision, id, geometry)` takes the geometry instead of reading it off
  the node: one cache key holds one payload, so a preview and the document each re-derive that node
  once when they take the entry over. Every untouched node stays cached, which the existing
  `a_rebuild_at_a_new_revision_reuses_every_unchanged_mesh` test still proves.
- The pull previews the body itself (`previewed_body`: the stored `Constructive` with one height
  changed), so the frame shows the solid the ✓ stores and the wireframe ghost became dead code.
- The bar lives in `crates/ui` (`command_bar.rs`) because it reuses `Scrub`, which is crate-private;
  the shell places it and hands it label, value, unit and range. Enter applies and Escape cancels,
  read after the field drew so a typed height is committed first. `Scrub::focus` was added so a
  fresh pull can be typed into without a click — the gizmo's `take_focus` clears the flag.
- The view cluster is lifted by `BAR_HEIGHT + 6` while a bar is up (`view_cluster::show` gained a
  `lift` parameter) rather than the bar hiding the cluster: the user can still orbit while pulling.
- The busy state is a 250 ms budget on the *measured* rebuild (`Rebuild` in `document.rs`). A scene
  whose last rebuild overran it defers the next rebuild by one frame: the frame that paints
  «Перестроение…» keeps the last good geometry and the work runs on the next one, so the message is
  true and the window answers input in between. A cheap scene never shows it and never pays the frame.
- `finish_extrude` is guarded by `extrude_writes(committed, height)`: the pull closes on the first
  finish, so a double click, a key and a button in one frame, or two clicks across frames all write
  once. `cancel_extrude` is the mirror: drop the pull, clear the overlay, re-evaluate.

## Ruled out

- Writing the preview into the document and undoing it on cancel: one undo entry per frame of a drag,
  a dirty file before the user accepted anything, and a cancel that is itself an edit.
- A second `Project` clone as the preview: the whole document would be copied per frame and the
  scene tree, picking and the inspector would have to decide which copy they read.
- Keeping the wireframe ghost beside the solid preview: two pictures of one decision.
- Hiding the view cluster while the bar is up: it takes the orbit controls away exactly when the user
  is judging an extrusion in space.
- Announcing every rebuild: U65's rule is a ~250 ms threshold, and a cheap rebuild's message is
  painted after the work, which is a lie.
- A blocking spinner or a modal for a slow rebuild: the window must stay usable.
- Wiring the boolean tools now: there is no boolean command, and inventing one inside this task would
  mix a feature with a UI surface. The overlay and the bar are ready for it (ADR 0093).
