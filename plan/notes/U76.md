# U76 — the ribbon holds tools only

## What was measured

- `crates/ui/src/toolbars/spec.rs`: `CellSpec` was a tool-or-field enum. Three `FieldSpec` rows
  (`sketch.create.sides`, `model.primitives.size`, `model.create.height`) took `COLUMNS = 2` cells
  each, so the *Sketch* row was 10 cells and the *Model* row 8.
- `crates/ui/src/toolbars.rs::show_field` drew an `egui::TextEdit` per field; `GroupSpec::columns`
  summed live tools plus two per live field.
- `crates/ui/src/toolbars/state.rs` kept the three values as `String` and parsed them into `Length`
  on every draw. Five `FieldRefusal` variants and five `furnicraft_text` messages existed only to
  explain a typo to a tooltip, and `ready()` turned a bad number into a disabled cell.
- The object card already owns the editors the fields duplicated: `figure_section` has `Sides` and
  a radius for a polygon, `primitive_section` has edge/radius/height/sides/bands, and the pull
  arrow's command bar has the extrusion height.

## Decisions

- `GroupSpec { id, label, tools: &'static [ToolSpec] }` is a list of tools; `CellSpec` and its
  `columns()` are gone, `GroupSpec::columns()` counts live tools, and `tools()` became
  `live_tools()` so the field and the method are not confused.
- `Toolbars` stores the three values typed (`primitive_size: Length`, `extrude_height: Length`,
  `polygon_sides: u32`), built from `DEFAULT_PRIMITIVE_SIZE_MM`, `DEFAULT_EXTRUDE_HEIGHT_MM` and
  `DEFAULT_POLYGON_SIDES`. `ready()` therefore always has a valid number; the primitive cell and the
  extrude cell are enabled by the scene alone.
- `Editor::set_extrude_height` writes the typed default after the command accepts the height, so a
  refused height leaves the default where it was; `Editor::extrude_height` replaces the old text
  getter. The pull's ✓ is still the only path that changes a body's height.
- ADR 0091 gained an amendment rather than a new record: the const-map decision stands, only the
  field clause is withdrawn. `plan/map.md` lost `CellSpec`, `FieldSpec`, `FieldRefusal` and the old
  text getter.

## Ruled out

- Keeping `CellSpec` with one `Tool` variant: a one-arm enum in the map is a leftover of a form the
  owner does not want, and `tools: &[ToolSpec]` reads as the design document does.
- A setter for the primitive size or the side count: no surface offers one now, and a public setter
  nobody calls is speculative. The card edits the object the default created; if a default needs its
  own editor, it belongs in the object/creation card, not the tool row.
- A new ADR: the decision is the amendment of one clause of 0091, not a second ribbon model.

## Verification

- `cargo xtask ci` green: 398 `furnicraft-ui` lib tests (including `no_tab_draws_a_text_field`,
  `the_ribbon_starts_on_the_typed_defaults`, `a_primitive_cell_runs_at_the_default_size`,
  `a_polygon_is_started_with_the_default_side_count`, `a_row_and_a_tab_count_tools_only`), plus the
  adapted pull test `a_pulled_height_becomes_the_next_extrusions_default`.
- The ribbon was drawn silently through `egui::Context::run_ui` for the no-field test; no live window
  was needed because the change removes widgets rather than paints new ones.
