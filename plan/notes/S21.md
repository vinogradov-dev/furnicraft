# S21 — the shell's Home surface moves out of `main.rs`

The S7 audit filed this split from a measurement that read one function's length as the distance to
the next item at column 0. `home_surface` sits at the end of `impl FurniCraftApp`, so the count ran to
`impl eframe::App` and reported 632 lines: the function itself is 30, and the other 602 are exactly
the tail S22 takes (status bar, folding side panels, strip geometry, shortcut readers).

## What was measured

- At `5748a95`, `fn home_surface` in `apps/furnicraft/src/main.rs` is 30 lines: guard, one
  `furnicraft_ui::home::show` call, and a `match` that hands each `HomeAction` to the File menu path.
- The start surface has lived in `crates/ui/src/home.rs` since `c83ace5` — `HomeAction`, `show`,
  `template_card` and `recent_row`, with its own 108-line test module — so the drawing, the layout
  and the tests are already out of the shell and in the layer that owns egui widgets.
- Real measures of the tail between `home_surface` and `impl eframe::App`: `viewport` 637 lines
  (the one finding the audit placed correctly, and U45's), the `StatusInfo` family ~180, the
  folding panels ~220, the strip helpers ~120, the shortcut readers ~70.

## Ruled out

- Creating `apps/furnicraft/src/home.rs` around a copy of `crates/ui/src/home.rs`: it would draw the
  same modal twice and pull UI layout code back up into the shell.
- Splitting the 30-line handler: it is under every ceiling of `plan/refactor.md` §3 and its one job
  (turn one action into a File menu operation) is what keeps Home on the same path as the header.

## Consequence

Closed as delivered by `c83ace5`; the tail the measurement swallowed is S22's work, unchanged.
