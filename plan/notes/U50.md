# U50 — What was measured

## What was measured

- The header row lived in `apps/furnicraft/src/side_panels.rs` already (`panel_header` and
  `count_chip`), not in `main.rs` as the hint said: S22 and U45 had moved the chrome out. `main.rs`
  only built the two `PanelHead` values — the tree passed `Document::node_count()`, the card
  `Editor::selected_nodes().len()`.
- `Document::node_count` was a cached field whose only reader was the chip; `refresh()` recomputed it
  with a `NodeQuery::any()` scan before every rebuild of the scene.
- The chevron was drawn inside a right-to-left layout, so it sat at the right edge of both panels;
  `PanelSide` already named the edge, it just was not read for the header.

## Decisions

- The chevron takes its edge from `PanelSide` and stays `actions::COLLAPSE`: the style guide (§19.4)
  fixes one direction convention for the pair (chevron right = collapsed), so a second, mirrored
  asset would be the same action drawn twice.
- Dropping the chip dropped the cache with it: the field, its refresh and its getter are gone, so a
  rebuild no longer queries the tree for a number nobody draws.
- The two tests read the finished frame — the header band is the only `surface` fill 26 pt tall, the
  glyph is a `Shape::Mesh` — so "no count" and "which edge" are asserted where the user sees them,
  not from the widget tree.

## Ruled out

- A mirrored chevron asset (`collapse-left`): a second file, a README row, a fallback test and a
  direction convention per side, for one glyph whose direction the guide already fixes.
- Keeping the count in the folded strip: the strip carries the icon and the turned title, and no
  reading of the scene needs a node total.
