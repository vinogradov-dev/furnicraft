# N13 — one fill cell, and its build method in the cell's own list

what the session measured about the two rows that looked like two panels

## What was measured

- `crates/ui/src/toolbars/spec.rs` declares two fill cells (`furniture.panels.post`, `.shelf`), each
  with one variant: `FILL_POST_SHAPE` / `FILL_SHELF_SHAPE`. The shape variant had `icon: None`, so the
  list's glyph column was blank for it (the header still drew the tool).
- `crates/ui/src/toolbars.rs::show_tool` built the main face from `state.pinned_index(tool)` only.
  Running the shape row armed the fill with `FillMode::Shape`, but the cell went on drawing the pinned
  Fit face and not pressed, so the choice looked like it did not take. The rows are `Method`s, not
  panels, but the list had no caption and no glyph on the second row to say so.
- `main_face` took `row.method.icon.or(tool.icon)`. Adding a glyph to the shape variant would therefore
  have replaced the post/shelf glyph on the cell as soon as the shape was pinned, turning the cell
  into a second-looking tool. The fill face needs the tool glyph in both modes.
- `Toolbars::pin` writes `ribbon.pinned_variants` to the workspace file. Running a row does not pin,
  by U74; the user's settings already pinned `furniture.panels.post.shape`, which is why a fresh
  session could open with one mode selected and the row the user clicked not.

## Decisions

- One cell per panel kind. The build is the cell's method list, captioned «Способ построения» /
  “Build method”, and the shape row carries `icons::contour::POLYGON` (ADR 0110).
- `main_face` always uses `tool.icon` for `ToolKind::Fill`, so the cell keeps saying Post/Shelf.
- The armed method wins over the pinned one for the face, its hint and its action. That makes the
  mode visible and the same click drops the tool; the pin remains the explicit workspace default.
- Rows renamed “Largest rectangle” / «Наибольший прямоугольник» and “Niche shape” / «По форме ниши»;
  the hint keeps the tool name in front.
- Ruled out: pinning on run (silently writes the settings file and contradicts U74's explicit pin);
  a separate tool cell per mode (the owner's complaint); a right-click context menu on the cell (a
  second floating surface and a `HOST_OWNERS` row for a choice the cell's caret already owns).

## Verification

- Headless: the two methods carry glyphs and the section caption; the open list draws “BUILD METHOD”
  and both rows; with Fit pinned and Shape armed the cell shows “Post: Niche shape”, pressed, keeps
  the post glyph and returns the Shape action; both rows keep the tool glyph on the face.
- Eyes: `target/ui-shots/fill-ghost.png` was rendered offscreen with the Furniture tab active and
  the shelf fill armed in Shape mode; the pressed cell draws the shelf glyph, not the polygon.
