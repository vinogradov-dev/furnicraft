# N11 — a panel end is beveled by an angle about its outline edge

a panel end is beveled by an angle about its outline edge

## What was measured

- `Panel` (`crates/model/src/panel/mod.rs:102`) stores the outline, banding, machining and the
  nominal size, and its body is `PanelPlan::solid` (`crates/param/src/machining.rs:163`): one
  `core` region extruded along `+Z` by the thickness, then a list of `PlanStep` booleans. A
  panel end face is always perpendicular to the two large faces; nothing can express a skew.
- The kernel already cuts a solid with a prism: `PlanBuilder`/`PlanStep::Difference`
  (`crates/param/src/solid.rs`), and the kernel test `panel_groove_and_chamfer_match_analytic_volume`
  (`crates/kernel-truck/src/lib.rs:324`) subtracts a triangular chamfer cutter this way.
- `extrusion_plan(profile, frame, height)` (`crates/param/src/lib.rs:289`) turns any
  `Profile::new(outer, holes)` into the `SolidPlan` a `Difference` step needs; `Frame` is an
  orthonormal origin/axes value, so the cutter can be placed at a segment without leaving the
  panel frame.
- The outline sources are already stable and shared by banding: `SegmentSource::{Edge, Corner,
  Ring}` (`crates/model/src/panel/contour.rs:149`) and `EdgeRef::{Rect, Ring}`
  (`crates/model/src/panel/machining.rs:121`). A bevel can key on the segment the banding keys on.
- The schema is 23 (`crates/model/src/project/mod.rs:58`) and the golden scene is one file
  (`crates/project/tests/golden/scene.fcs`); ADR 0096 says a bump changes the layout, deletes the
  old loader and updates the one golden.
- A band strip follows its segment's nominal geometry (`build_shaped_bands`,
  `crates/param/src/lib.rs:299`); a beveled end face and a straight band cannot both be exact on
  the same edge.

## Decisions

- The parameter is one signed angle per outline edge, measured about the edge's line across the
  thickness. The outline is the edge on face `B`; face `A`'s edge is set back by
  `t * tan(beta)`. Positive removes material, negative is refused so the body never grows past
  its outline and the nominal size stays the stock size.
- One angle through the `B` edge determines a plane exactly: the `A` edge is parallel to the
  `B` edge (the same wall plane meets two parallel faces), so the end face through both is the
  plane the wall asks for. This is why a plane normal is not stored: the angle is editable and
  the edge line supplies the rest.
- The cutter is a wedge prism: a triangle in the plane across the edge, from the B edge to the
  A edge, extruded along the segment with the 1 µm overshoot. It folds as a `Difference` step
  after the core extrusion, so the analytic rectangle path, the core region, cutouts and the
  other edges' attachments stay as they are. A `Loft` between two rings would add a second body
  builder for nothing the kernel cannot do.
- One record per source, a line segment only (an arc's end face is a ruled surface, not a plane),
  `|beta| < 89` degrees, and the resolved body must keep one piece and a positive thickness.
  The command builds the plan before it writes, so a bad angle is a typed refusal.
- A beveled edge cannot carry a band: the band would follow the nominal edge and hang in the
  air. `panel.bevel.set` refuses a banded edge and the banding commands refuse a beveled one.
- Schema 24 with the golden updated; the card shows the angle and a clear action.

## Ruled out

- A stored cut plane (normal plus offset): it is one more thing to validate, and the angle about
  the edge is the same plane in a form a maker can read and edit.
- Two outlines, one per face: a polar change to `PanelOutline` and the ring generator, for a
  shape one angle already describes.
- A boolean union for a growing bevel: the body would exceed the stored outline and the nominal
  size would stop being the stock size; N12 chooses the reference face instead.
- Extending bevels to arcs now: an arc's end face is curved and no single plane matches a flat
  wall; refuse it with a sentence.
Anchors re-read: `Panel` `panel/mod.rs:103`, `PanelPlan::solid` `machining.rs:164`, `build_shaped_bands` `param/lib.rs:294`.
## What the build taught (N11, the session that built it)

- **The kernel refuses a plane through the panel's own edge.** A cutter whose tilted plane passes
  exactly through the outline edge of face `B` is tangent to the body there, and truck answers the
  difference with `Difference produced no solid` (or `This wire is not simple`). Tested at 0, 0.001,
  0.01, 0.1 and 1 mm of overshoot with several profile shapes: no overshoot of the other faces helps,
  only moving the *plane* off the edge does. `build_bevel_tool` therefore puts the plane 1 µm outside
  the material (below the document's own resolution) and closes the rest of the profile outside the
  panel; the measured volume is 73801.8 instead of the analytic 73800 for a 45° bevel on
  100 × 50 × 18, so the tests allow 5 mm³ on one bevel and 10 mm³ on two.
- **The cutter frame**: local X is the edge's `Line::left_normal()` (into the body for a
  counter-clockwise ring), local Y is world `Z` (the thickness) and local Z is the edge direction, so
  `Frame::from_origin_axes` gives a right-handed frame whose `x × y = z`. The profile lives in
  `(across the panel, thickness)`.
- **The far-face check needs the nominal size as an argument.** `Panel::bevel_violation` erodes the
  core by every full setback; the erosion band is anchored on the *nominal* segment, so a resize
  candidate must be checked with `nominal_segments_for(candidate)` — using the stored size makes the
  band land outside the narrower core and the check silently passes.
- **The erosion band leaves an outward bow out of the cut**, so a bowed neighbour can leave a
  crescent of core the bevel does not reach; one test window (a steep angle on the top edge of a
  panel with a bowed right edge) is therefore not a clean "removes everything" case.
- `Contour::new(segments)` is the ring constructor in the model (there is no `Contour::from_segments`
  in `crates/model`), and `ContourSegment::arc(centre, radius, start, sweep)` builds the quarter arc
  the arc-refusal test needs.
- `thiserror` reads a field named `source` as the error's source: the bevel error variants therefore
  name it `on`, and `EdgeRef` gained a `Display` (`edge 1`, `ring segment 3`) so those sentences read
  as English.
