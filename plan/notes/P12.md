# P12 — What was measured

## What was measured

- The legend was a four-line prose paragraph in `plan/BACKLOG.md` and no code read it: `cargo xtask
  plan` never compared the id prefixes with it, so two live phases (T, K) and R1 had no clause at
  all and nothing noticed.
- `cargo xtask file` refuses `plan/BACKLOG.md` on purpose (`test: the writer keeps its litmus` — the
  reference-file writer only takes map/debt/questions/refactor/rename), so the paragraph could only
  be fixed by a hand edit the rules forbid.
- The write path is `edit` (text in, text out) plus `apply` (the gate over the result, then a temp
  file). A verb therefore only has to produce a plan that passes the gate; it does not need to know
  which violations the old text had.
- The id prefixes in use today: A, D, G, K, M, N, P, R, S, T, U, V, X. The old paragraph declared A,
  B, C, D, E, F, G, H, P, L, S, V, X, U — so it was missing K, M, N, R and T, and declared six
  letters no id uses.

## Decisions

- **The legend has a canonical form and the writer alone produces it.** The lead line
  (`Phases come from the shape-base plan; `cargo xtask task phase` owns this list:`) is followed by
  one clause per letter — `` `A` — contour `` — wrapped at 100 with two-space continuations and
  sorted by letter. Parsing is unambiguous (a backticked capital letter and an em dash), the diff of
  a one-letter change touches one line, and the gate can name a line it does not accept.
- **`task phase <L> --name <text>` declares or updates one letter; `--declare "L=text"` may repeat.**
  Several letters in one write is not convenience: a file whose legend is still prose is refused by
  the new gate at every intermediate state, because the ids already use more letters than the one a
  single-letter write would leave declared. The whole vocabulary therefore travels in one gated
  write, supplied by the session that read the old paragraph — the tool never guesses it.
- **`task add --phase K --phase-name "…"` declares the letter and adds the task in one write**, so
  the first task of a new phase costs one command. Without `--phase-name` the phase must already be
  declared, and the refusal names the verb that declares it.
- **The check is conditional: no legend, no rule.** `state-contract` is a reusable tool and a
  project may not name its phases; the gate only holds a file to a legend that exists. Once it
  exists, every id prefix must be declared (declared-but-unused letters are allowed: the vocabulary
  can run ahead of the work).
- **The legend is still the intro paragraph, not a `## Phases` section.** The backlog's sections are
  the work order; a legend is vocabulary, and a new section would need its own heading rules and
  would move the owner's paragraph rather than keep it in place.
- **This project's legend was migrated in one write with 19 clauses.** The six unused-but-declared
  letters (B, C, E, F, H, L) kept their text so nothing was dropped, and the five undeclared ones
  were named from their tasks: K the contract other programs read, M a milestone's own work, N the
  furniture product, R the pre-release rename, T the semantic classes. The wording is the session's
  reading of those tasks; `task phase T --name "…"` renames any of them in one gated write.

## Ruled out

- **A tolerant parser for the old prose.** Splitting `A contour, B contour operations, … and U is
  the UI: …` at commas is a guess: the clause text itself carries commas and an `and`. A silent
  mis-split would drop a phase's meaning, which is exactly the drift this task exists to stop, so
  the session supplied the whole legend through `--declare` instead and the gate proves the result.
- **`## Phases` as a section with a line per letter.** It compiles and validates beautifully, but it
  moves the legend out of the intro prose the owner wrote and gives the file a fifth section whose
  meaning is not the work order.
- **Declaring one letter per write while the legend is prose.** Every intermediate state is refused
  by the gate (the ids already name letters the rewritten legend does not), so the migration could
  not land at all.
- **Making the legend mandatory for every project the tool scaffolds.** `cargo xtask init` would then
  have to invent phase letters for a project that has no plan phases.
- **Letting `add --phase` create a legend-less phase silently.** The point is that the vocabulary and
  the ids agree; a task in a phase nobody explained is the defect P12 was filed from.

## Verification

- `cargo test -p state-contract`: 185 lib tests, including a prose legend reported rather than
  guessed, a partial rewrite that drops a used letter refused, `--declare` twice in one write, and
  `add --phase K --phase-name` landing both the clause and the task.
- `cargo xtask plan`: green over the migrated legend; a plan whose id names an undeclared letter
  fails with the sentence that names `cargo xtask task phase`.
- `cargo xtask ci`: green.
