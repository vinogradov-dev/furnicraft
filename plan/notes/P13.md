# P13 — What was measured

## What was measured

- `parse_state` required `task=` to be a non-empty value, and `analyze` matched it against the
  backlog: a value that is not a task id was "not a task in `plan/BACKLOG.md`". There was no way to
  say "no task is scheduled".
- `close` ended with `first_open(&tasks).ok_or_else("no unfinished task is left in `## Now`; set
  `STATE:` for the next milestone by hand")`, and `defer` refused the same case, so a plan could not
  be left with an empty order at all — which is exactly the state R1, K2, K3 and K4 were just put in.
  P12's own session ended with a finished task still marked `[~]` because the order could not be
  emptied; that is the defect this task removes.
- `take` already had the branch the other way round: "into an empty one it makes the taken task
  current", and its comment names the same repair. So the missing half was the empty state itself,
  not moving entries.
- `next_violation` required `## Next` to name the current task, and `report` looked the current task
  up by id, so both needed a case for "there is none".

## Decisions

- **`task=-` is the empty order.** `-` is the file's existing "none" marker (`phase` renders as `-`
  when absent), so nothing new is invented and a reader sees one convention. `State::current()`
  maps it to `None`; every other consumer keeps reading `state.task` as a string.
- **The gate allows `task=-` only while `## Now` holds nothing unfinished.** The moment a task is in
  the order the line names it: the arrow in the status block has one meaning, and a plan that says
  "nothing is scheduled" next to a scheduled task is the contradiction the gate exists for.
  `state=doing` with `task=-` is refused with its own sentence.
- **`## Next` says `Nothing is scheduled` in words.** The paragraph is the first prose a session
  reads; with no task to name it must describe the empty order instead, so the gate requires it to
  open with that sentence and the writer produces it with a count of the parked work. A close or a
  defer that empties the order writes the sentence in the same validated write, so no second command
  is needed and no violation appears in between.
- **`take` needed no change.** Its "unoccupied" branch already makes the taken task current and
  writes the paragraph; the only difference is that it now repairs a *legal* state (`task=-`) rather
  than an impossible one.
- **The read side renders the empty order instead of failing.** `status` prints
  `-> Nothing is scheduled: `## Now` is empty, the backlog keeps the work` and lists the parked tasks
  without the arrow; `cargo xtask next` and `cargo xtask task` with no id print that same block
  rather than looking up a task called `-`. `--md` and `--paths` print nothing, because a task that
  does not exist has no fields and no paths.
- **The session contract gained a fifth answer.** `templates/AGENTS.section.md` now says that an
  empty order is answered by saying so and naming what waits in `## Next` — never by inventing a
  task and never by taking one into the order unasked.

## Ruled out

- **Omitting `task=` from the `STATE:` line.** The parser requires the key and the template writes
  it; a missing key would make "nobody set it" and "nothing is scheduled" the same text, and the
  gate could not tell a truncated line from an intentional decision.
- **`task=none` or `task=empty`.** A word in a field that otherwise holds ids is read as an id by
  `first_id`-style scans and by anyone grepping the plan; the single dash cannot be mistaken for one.
- **Letting `close`/`defer` write `task=-` and leave the old paragraph.** The gate would refuse the
  result (the paragraph names a task that is no longer current), so the write would need a
  `--repair` that hides a mistake instead of a default that states the fact.
- **A `## Now` placeholder task ("the next task is undecided").** That is the invented work this
  task removes, and it would have to be closed eventually, putting the same problem back.
- **Relaxing the rule that `STATE: task=` is the first unfinished task in `## Now`.** It is what
  makes the order meaningful; the empty order is a separate, explicit state rather than a hole in
  it.

## Verification

- `cargo test -p state-contract`: 189 lib tests and 25 integration tests — deferring the last task,
  closing the last task, `task=-` with a task still in `## Now`, an empty order with a paragraph
  that names a parked task, taking a parked task back, the status block's
  `-> Nothing is scheduled` line and its unmarked parked entries.
- `cargo xtask ci`: green.
- Live: this session closed P13 and the plan now sits at `task=-` with
  `Nothing is scheduled: 4 open tasks wait in `## Next`.` — the state that was impossible before.
